# 실기기 수용 기록

## RC31 OS 모니터 배치·해상도·배율 수용

- [ ] RC31로 갱신하고 확장 갱신·GNOME 재로그인 후 모니터 설정 화면이 지원 모드를 표시한다.
- [ ] 실제 화면의 식별 번호와 출력 선택을 맞추고, 세 대 이상·상하·여러 줄 배치에서 드래그·드롭을 확인한다.
- [ ] 드롭 전 상대는 움직이지 않고, 드롭 때 위치를 바꾼다. 사이트는 기존 출력에 유지된다.
- [ ] 다른 해상도·크기의 모니터를 교환하고 제삼 출력이 임의로 이동하지 않는다.
- [ ] 출력별 지원 해상도·주사율·배율을 선택한다. 미지원 배율은 재선택하고 겹침·불연속 배치를 적용하지 않는다.
- [ ] 배치 적용 후 실제 화면을 보고 유지·복원·30초 미확인 복원을 각각 확인한다.
- [ ] SSH 종료·실행기 종료·확장 비활성화·연결 변경에서 복원 관측 또는 복구 필요 상태를 확인한다.
- [ ] 저장한 배치가 운영자 재로그인·재부팅 후 같은 연결 구성에 복원되고 Chrome의 사이트 배정이 유지된다.
- [ ] 다른 모니터·모드·회전·계정 조건에서는 저장 프로필을 강제 적용하지 않는다. 같은 세션의 수동 변경과 자동 복원 끄기를 존중한다.

위 항목은 실제 Rocky/GNOME/패널 수용용이다. 모의 회귀·SVG 미리보기·일반 Linux CI로 완료 표시하지 않는다.

## 초기 안내·모니터 식별·두 화면 교환 수용

- [ ] 새 설치에서 일반 사용자 Chrome 안내가 모든 활성 논리 출력에 표시되고 자동 시작이 켜져 있다.
- [ ] 그래픽 세션 준비 전 설치·SSH 종료·재접속·다음 로그인에서도 초기 준비가 이어지고 DID가 중복 생성되지 않는다.
- [ ] 기존 미설정 장비는 옵션을 명시적으로 선택해야 초기화되며, 기존 사이트·수동 중지·저장된 꺼짐은 임의 변경되지 않는다.
- [ ] TUI 번호·안내 HTML·10초 식별 표지가 일치한다. 복제·배율·회전·음수 좌표에서도 배치와 포커스가 유지된다.
- [ ] 안내에서 사이트 주소를 저장하고 적용하면 선택한 DID만 전환되며, 안내 상태를 사이트 정상으로 표시하지 않는다.
- [ ] 사이트↔사이트·사이트↔안내를 교환하고, 중지된 상대는 중지 상태를 유지한다.
- [ ] 교환 중 SSH 종료·한쪽 수동 중지·모니터 연결 해제·작업 중단 후 이전 배정 복구 또는 확정된 새 배정 정리를 확인한다.
- [ ] 복구 확인 불가는 대상별 상태와 복구 재시도를 표시하며, 다른 DID는 계속 운영한다.
- [ ] 재부팅 후 확정 배정과 로그인 자동 시작이 유지되고 `ala --version`은 비대화형에서도 버전 한 줄만 반환한다.

위 항목은 실제 Rocky/GNOME/패널 수용용이다. 모의 회귀나 Node 확장 harness로 완료 표시하지 않는다.

## RC3 추가 수용 — 아직 실기기 미수행

- CPU 서버: prepare 계획/적용 → 필요시 직접 재부팅 → SSH 재접속 → prepare 재실행으로 예상 커널 검증 → setup 적용.
- prepare 완료 후 재실행에서 전체 업데이트와 기록 mtime이 반복 변경되지 않는지 확인.
- doctor network에서 장치/실행 커널 모듈/펌웨어 초기화/연결 계층 확인. 유선 성공을 Wi-Fi 성공으로 기록하지 않음.
- display/autologin=true, URL 미입력 상태에서도 직접 재부팅 후 바탕화면 진입 확인.
- autostart=false로 Chrome 자동 실행만 끈 뒤에도 자동 로그인 유지 확인.
- URL 입력+autostart=true에서 다시 적용하고 재부팅 후 Chrome 전체화면·번역/복원/키링 팝업 부재 관찰.
- 기존 암호/SSH 인증·다른 Chrome 프로필 보존 및 화면 잠금/절전 방지 확인.
- GPU 서버: 드라이버 미설치 시 OS 준비부터 진행, 기존 NVIDIA/DKMS가 있으면 prepare 차단이 기대 동작.
- 호스트 nvidia-smi 및 실제 GPU 컨테이너 실행 검증.

모의 테스트/프로세스·세션 검사만으로 화면 수용을 완료 처리하지 않습니다. 현재 실제 장비 설치·재부팅·화면 수용은 미검증입니다.

## RC17 설정/관리 분리 수용 — 아직 Rocky 실기기 미수행

- Chrome 중지 상태에서 간편 설정 첫 적용/재실행 후에도 현재 Chrome이 시작되지 않고 자동 로그인·부팅 등록만 준비되는지 확인.
- Chrome 실행 상태에서 간편 설정 재실행 전후 PID·프로필·표시 내용이 유지되는지 확인.
- TUI 화면 관리에서 시작·중지·재시작·상태·로그를 키보드로 조작하고 설정 준비/현재 실행/사이트 감시를 구분하는지 확인.
- 직접 재부팅 후 부팅 ID 변경 → SSH 재접속 → 지정 사용자 그래픽 세션 → 자동 시작 서비스/검증된 Chrome 자식/최신 감시 상태 → 실제 모니터의 전체화면 순서로 확인.
- 현재 실행 중지는 다음 로그인 자동 시작을 끄지 않는지, 자동 시작 off 적용 후에는 다음 로그인에서도 시작하지 않는지 확인.
- Chrome의 별도 systemd scope에서도 PPid/UID/시작 식별자 검증이 정상 동작하고 무관·재사용 PID는 정상으로 판정하지 않는지 확인.
