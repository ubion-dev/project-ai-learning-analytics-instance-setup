# 실기기 수용 기록

## RC22 화면 설정과 HDMI 수용

- [ ] HDMI 연결·분리 후 DRM 상태가 바뀌고 GNOME 재로그인 후 활성 출력과 창 배치가 확인된다.
- [ ] 버튼 포커스와 마우스 올리기로 설명을 확인할 수 있고, 80×24에서 적용 상태와 버튼이 보인다.
- [ ] 사이트 저장 후 현재 주소가 유지되고, 설정 적용 후 선택한 화면만 새 주소로 전환된다.
- [ ] 준비 실패 시 기존 표시를 유지하고, 시험 실행 실패 시 이전 설정으로 복원한다.
- [ ] 현재 확정된 화면 코드와 대기 중인 코드 후보가 설정 적용 후에도 구분된다.

## RC21 화면·자동 운영 수용

아래는 아직 실기기 미수행이다. 모의 테스트·headless Chrome 결과로 체크하지 않는다.

- [ ] GNOME 47 확장 로드, 출력 1/2/3개·복제·재연결의 배치도/창 수 구분
- [ ] 대상별 실제 전체화면과 좌우 테스트 배치·수동 시작/중지/재시작
- [ ] CLI만 갱신할 때 Chrome PID·표시·탐색 유지와 고정 관리 버전 유지
- [ ] 실제 서명된 배포와 현재 설치 manifest 검증, 최초 이전 후 구성 저장
- [ ] 야간 대상별 전환·다른 화면 유지·실패 복원·수동 중지 우선
- [ ] 컴퓨터 정상 재부팅 후 자동 로그인·지정 출력의 창 복구
- [ ] 프론트 새 빌드·ready 연동, 동일 빌드 재로딩 없음·장애 안내/자동 복귀
- [ ] 수용 확인 전 자동 운영 꺼짐, 켠 뒤 timer와 적용 결과 확인

서명 release workflow의 보호 환경·태그 규칙 실제 설정과 첫 Sigstore 서명 릴리스
발행·검증도 별도 배포 조건이다. 이번 코드 변경만으로 설정됐다고 기록하지 않는다.

## 현재 판정

**미수행**. 이 문서에 테스트 결과를 작성하기 전에는 실제 설치·GUI·GPU·재부팅 수용을 통과한 것으로 간주하지 않습니다.
로컬 모의 검사 통과만으로 정식 `v0.1.0`을 배포하지 않습니다.
실제 대상 장비의 접속 경로와 기기 식별을 확인한 뒤 검증합니다.

## 준비

담당자가 CPU/GPU 대상 서버, SSH 연결 경로, 기존 sudo/화면 계정, 로그인 없는 DID URL, 유지보수 시간과 화면 확인 방법을 정합니다.
인증 비밀번호·토큰·쿠키를 이 문서나 GitHub에 기록하지 않습니다. 운영 데이터가 있는 서버에서는 백업과 점검 범위를 먼저 확인합니다.

## RC3 추가 수용 — 아직 실기기 미수행

- CPU 서버: prepare 계획/적용 → 필요시 직접 재부팅 → SSH 재접속 → prepare 재실행으로 예상 커널 검증 → setup 적용.
- prepare 완료 후 재실행에서 전체 업데이트와 기록 mtime이 반복 변경되지 않는지 확인.
- doctor network에서 장치/실행 커널 모듈/펌웨어 초기화/연결 계층 확인. 유선 성공을 Wi-Fi 성공으로 기록하지 않음.
- display/autologin=true, URL 미입력 상태에서도 직접 재부팅 후 바탕화면 진입 확인.
- autostart=false로 Chrome 자동 실행만 끈 뒤에도 자동 로그인 유지 확인.
- URL 입력+autostart=true에서 다시 적용하고 재부팅 후 Chrome 전체화면·번역/복원/키링 팝업 부재 관찰.
- 기존 암호/SSH 인증·다른 Chrome 프로필 보존 및 화면 잠금/절전 방지 확인.
- GPU 서버: 드라이버 미설치 시 OS 준비부터 진행, 기존 NVIDIA/DKMS가 있으면 prepare 차단이 기대 동작.
- 호스트 nvidia-smi 및 실제 GPU 컨테이너 실행 검증.

모의 테스트/프로세스·세션 검사만으로 화면 수용을 완료 처리하지 않습니다. 현재 실제 장비 설치·재부팅·화면 수용은 미검증입니다.

## RC16 추가 수용 — 아직 Rocky 실기기 미수행

- TUI 업데이트 관리에서 명시적 갱신 → 진행 중 창 닫기 → 재접속 → 완료/실패와 설치 버전 조회. 새 버전 설치 뒤 오래 열린 TUI의 재실행 안내 확인.
- 통제된 배포 경로 장애·다운로드 실패 시 결과와 현재 설치 버전을 확인. 확인 불가를 완료나 기존 버전 유지로 오인하지 않는지 확인.
- 로그인 없는 합성 표시 페이지에서 정상 → 주 문서 404/서버 오류/연결 실패 → 로컬 복구 안내 → 복구 후 원래 페이지의 실제 전체화면을 관찰.
- 정상일 때 주기적 새로고침이 없고, 하위 아이콘/이미지 오류만으로 전체 페이지를 전환하지 않는지 확인.
- 표시 서비스 중지·Chrome 종료·탭 종료·반복 실패 제한 및 다음 부팅 복구 확인. 관리 밖 Chrome과 기존 프로필이 유지되는지 확인.
- Mac의 격리 headless 브라우저/로컬 HTTP 검증은 transport·상태 전이 증거이며 Rocky GNOME의 실제 화면 수용을 대신하지 않음.

## RC17 설정/관리 분리 수용 — 아직 Rocky 실기기 미수행

- Chrome 중지 상태에서 간편 설정 첫 적용/재실행 후에도 현재 Chrome이 시작되지 않고 자동 로그인·부팅 등록만 준비되는지 확인.
- Chrome 실행 상태에서 간편 설정 재실행 전후 PID·프로필·표시 내용이 유지되는지 확인.
- TUI 화면 관리에서 시작·중지·재시작·상태·로그를 키보드로 조작하고 설정 준비/현재 실행/사이트 감시를 구분하는지 확인.
- 직접 재부팅 후 부팅 ID 변경 → SSH 재접속 → 지정 사용자 그래픽 세션 → 자동 시작 서비스/검증된 Chrome 자식/최신 감시 상태 → 실제 모니터의 전체화면 순서로 확인.
- 현재 실행 중지는 다음 로그인 자동 시작을 끄지 않는지, 자동 시작 off 적용 후에는 다음 로그인에서도 시작하지 않는지 확인.
- Chrome의 별도 systemd scope에서도 PPid/UID/시작 식별자 검증이 정상 동작하고 무관·재사용 PID는 정상으로 판정하지 않는지 확인.
