# 텍스트 CLI 사용

RC36의 기본 `ala`는 숫자와 Enter로 사용하는 메뉴다. 화면을 지우거나 마우스를 캡처하지
않고 입력 대기 중 조회·다시 그리기를 하지 않는다. SSH 포트 포워딩이나 브라우저 없이
일반 SSH 터미널에서 사용한다. HIWARE의 실제 명령 허용·장비 접속 정책은 기관이 결정한다.

## 진입과 공통 입력

- `ala` / `ala console`: 기본 메뉴.
- `ala screen` / `ala chrome`: 사이트·Chrome.
- `ala display edit`: 모니터 배치·해상도·화면 배율.
- `ala config edit`: 화면 계정·기본 구성.
- `ala tui`: 기존 전체 화면을 명시적으로 사용.

번호와 Enter로 선택하고 `b`는 한 단계 돌아간다. 입력 항목의 Enter는 표시된 기존값을
유지한다. `yes`는 저장·적용·운영 변경 승인이고 다른 입력이나 Enter는 실행하지 않는다.
EOF/Ctrl+C로 표시를 끝내도 접수된 작업은 서버에서 계속된다. 미저장 초안은 폐기된다.
조회 후 보이는 상태는 그 시점의 결과이며 최신 상태가 필요하면 다시 조회한다.

## 모니터

`ala display edit` → 모니터 번호 → 위치/해상도/배율을 선택한다. 위치는 좌표, 다른 모니터와
교환, 기준 모니터의 좌·우·위·아래를 제공한다. 세 대 이상에서도 선택한 출력만 편집하며
다른 출력을 자동으로 밀지 않는다. 겹치거나 빈틈이 있는 배치는 적용 전 검증에서 거부한다.

해상도는 해당 출력의 지원 모드이며 긴 목록은 12개씩 표시한다. `n`/`p`로 다음/이전 쪽을
보고 표시된 절대 번호를 입력한다. 배율은 선택 모드의 지원 값만 제공한다. 모드 변경으로
기존 배율이 지원되지 않으면 미선택으로 두며 다시 선택하기 전에는 적용하지 않는다.

`a`로 이전/이후를 검토하고 로그인 유지 여부를 선택한다. `yes`로 OS 적용을 요청하고
실제 모니터를 확인한 뒤 30초 이내에 다시 `yes`로 유지한다. Enter는 복원 요청이며
미응답/연결 종료 시에도 서버의 기한과 복원 작업은 독립적으로 유지된다. 이미 진행 중인
배치가 있으면 새 편집 대신 그 작업의 확인·복구를 제공한다. 기한 뒤에는 유지할 수 없다.
로그인 복원 상태·끄기·재시도는 `p`, 모니터 식별은 `i`다.

## 사이트·Chrome

`ala screen` → 대상 번호 → 설정 편집. URL·출력 ID·창 배치·자동 시작·프론트 배포 감지를
편집한다. URL에 `-`를 입력하면 로컬 안내 화면을 선택한다. 출력의 `-` 자동 선택은 기본
대상에서만 제공한다. 새 화면은 `n`에서 ID를 지정하고 저장 후 간편 설정에서 등록한다.

저장과 실제 적용은 별도이며 각각 확인한다. 다른 작업에서 구성을 바꿨으면 저장/적용을
거부한다. 시작·중지·재시작·페이지 새로고침·로그·코드 전환·배포 재시도·두 사이트 출력
교환·교환 복구를 대상별 메뉴에서 선택한다. 작업 접수는 실제 화면 정상 확인이 아니다.
적용 뒤 `r`로 다시 조회하거나 현장에서 실제 화면을 확인한다. 로컬 초안과 마지막 조회
결과를 혼동하지 않으며 명시 조회 없이 정상 상태를 추정하지 않는다.

## 설치·상태·업데이트·고급

기본 `1` 간편 설정은 현재 저장 구성과 계정을 확인하고 `yes` 후 접수한다. 활성 설치
작업만 2초마다 추적하고 변경된 진행 항목만 출력한다. 기존 사이트·Chrome 프로필·수동
중지와 코드 선택은 기존 엔진의 정책으로 보존한다. `2`는 상태를 한 번 조회한다.

`5` 업데이트에서 조회·갱신·상태·정책을 명시적으로 선택한다. 기본 메뉴를 여는 것만으로
릴리스 API에 접속하지 않는다. `6` 고급에서 기본 설정·실행 기록/로그·네트워크 진단·OS
준비·확장 갱신·로그인 진단·DID 초기화/복구·자동 운영·미사용 Podman 정리 검토를 제공한다.
자동 운영 활성화는 실제 장비의 화면·야간 적용 수용을 마친 뒤에만 승인한다.

## 비대화형 명령

기존 하위 명령과 JSON 출력을 유지한다. 예:

```sh
ala check --json
ala display list --json
ala display modes --json
ala display plan layout.json --json
ala display apply layout.json --json
ala display trial-status --json
ala display confirm --operation-id OPERATION_ID --json
ala config show --json
ala config import instance.json
ala chrome status --target default --json
ala update --status --json
```

`layout.json`은 조회한 edit_template을 기준으로 수정한다. 모니터·구성 revision이 바뀌면
다시 조회하고 검토한다. `display apply`는 로그인 유지, `display trial`은 세션 시험이며
둘 다 서버 확인 기한과 복원 계약을 적용한다. 메뉴는 TTY가 필요하며 파이프에서는 명시
하위 명령을 사용한다. 실제 Rocky/HIWARE의 키 입력·출력·화면 수용은 모의 검사와 구분한다.
