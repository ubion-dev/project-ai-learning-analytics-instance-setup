# 업데이트와 최초 이전

## RC41 비례 배치도와 고정폭 리모컨

`ala update --prerelease` 후 ala를 다시 실행해 `0.1.0rc41`을 사용한다.
배치도는 논리 화면의 위치·크기를 동일 축척으로 표시한다. 작은 세로 오프셋도 축척에 따라 표시하고,
해상도·배율·회전에 따른 크기를 반영한다. 셀 단위 반올림으로 한 칸 차이가 날 수 있다.
도형에 정보가 잘리면 별도 모니터 정보를 제공하고 축소할 수 없는 배치는 좌표 목록으로 표시한다.
고정폭 십자 리모컨에 선택·기준 번호를 표시하며 포커스를 둔 상태에서 방향키로 기준의 상하좌우에 붙인다.
선택 목록의 방향키 조작과 검토·적용·30초 확인/복원 절차를 따른다. 재부팅 없이 CLI 재실행으로 새 UI를 사용한다.

## RC40 화면 관리 내 리모컨·기본값 초안

`ala update --prerelease` 후 ala를 닫고 다시 실행해 `0.1.0rc40`을 사용한다.
모니터 설정을 같은 화면 관리 탭 안에서 펼치며 십자형 리모컨·출력별 해상도·화면 배율과 미적용 초안을 표시한다.
처음 펼칠 때만 모드를 조회하고 접기는 초안을 보존한다. 전체 기본값은 사이트를 보존하는 권장 모드·100%·가로 정렬 초안이다.
미지원 값에는 전체 초안을 보존하고 중단한다. 기존 검토·적용·30초 확인/복원을 사용한다.
다른 사이트가 점유한 출력은 선택 목록에서 제외하며 자기 출력·겹치지 않는 좌우 분할은 유지한다.
기존 구성·API·과거 교환 복구·재부팅/재로그인 정책은 유지한다.

## RC39 드래그 제거·상하좌우 배치 설정

`ala update --prerelease` 후 기존 ala를 닫고 다시 실행해 `0.1.0rc39`를 사용한다.
배치도는 화면 관리 탭의 읽기 전용 보기로만 제공한다. 실제 좌표의 상하/좌우 관계를 유지하고
가로 공간이 부족하면 잘못 줄바꿈하는 대신 좌표 목록으로 표시한다. 클릭·Enter는 사이트 설정만 연다.
사이트 이동·모니터 이동의 드래그와 마우스 캡처를 제거했다.
모니터 설정은 대상·기준 모니터와 왼쪽·오른쪽·위·아래 버튼으로 단순화했다. 별도 배치 캔버스,
위치 팝업, 좌표 입력, 위치 교환은 TUI에서 제공하지 않는다. 초안·검토·적용·30초 확인/복원과
단일 출력/미선택 기준의 방향 버튼 차단을 유지한다. 기존 비대화형 배치 JSON API와 과거 교환
기록 복구는 보존한다. 이번 UI 변경만을 위한 재부팅·GNOME 재로그인·설정 초기화는 필요 없다.

## RC38 드래그 없는 모니터 위치 변경

`ala update --prerelease` 후 기존 ala를 닫고 다시 실행해 `0.1.0rc38`을 사용한다.
`ala display edit`에서 모니터를 선택하고 **위치 변경(P)**으로 기준 모니터의 좌우·상하·위치
교환 또는 정확한 좌표를 정한다. 초안만 반영하며 별도의 변경 검토·배치 적용·30초 확인을
유지한다. 사이트는 기존 출력에 유지하고 콘텐츠 변경은 각 출력의 사이트 설정에서 수행한다.
여러 PC는 각각 접속해 설정하며 통합 PC 간 교환을 제공한다는 의미가 아니다.
새 위치 창은 추가 장비 조회나 원격 조작 없이 기존 초안을 편집한다. 취소·겹침·편집 상태
변경을 차단한다. 이번 UI 변경만을 위한 GNOME 재로그인·재부팅·설정 초기화는 필요 없다.

## RC37 기본 TUI 복원

화면 관리, `ala display edit`는 모니터 편집, `ala config edit`는 구성 편집 TUI를 연다.
RC36에서도 즉시 TUI가 필요하면 `ala tui`를 사용한다. 텍스트 메뉴는 `ala console`로만
명시 선택한다. 같은 업데이트 안내·대상 상태 문구를 반복해서 다시 그리지 않으며 실제 변화는
계속 표시한다. 가시성과 기존 설정·보존·확인/복원 계약을 유지한다. 실제 HIWARE 지연 개선은
별도 확인 대상이다. 이번 변경만을 위한 재부팅·GNOME 재로그인·설정 초기화는 필요 없다.

## RC36 기본 텍스트 메뉴

`ala update --prerelease` 후 실행 중인 ala를 종료하고 다시 실행해 `0.1.0rc36`을 사용한다.
기본 진입·`ala console`·`ala chrome`·`ala config edit`는 번호 기반 텍스트 메뉴이며,
`ala screen`과 `ala display edit`로 사이트·모니터 편집을 바로 연다.
마우스·전체 화면 다시 그리기·백그라운드 업데이트 조회를 사용하지 않고 명시 조회와 활성
작업 추적만 실행한다. 사이트·모니터 편집은 저장·적용 전까지 로컬 초안이다.
이 변경만을 위한 재부팅·GNOME 재로그인·간편 설정 재실행은 필요 없다.
기존 TUI는 `ala tui`로 유지한다. 실제 HIWARE 경유 반응 시간은 별도로 수용한다.

## RC35 모니터 편집 반응 개선

`ala update --prerelease` 후 실행 중인 `ala`를 닫고 다시 실행해 `0.1.0rc35`를 사용한다.
모니터 선택·좌표 편집 시 같은 해상도·배율 목록을 다시 만들지 않으며, 모니터 그림은
같은 스타일의 문자들을 묶어 그린다. 사이트 설정의 접힌 상세 로그는 처음 펼칠 때
생성하고 초기 입력 이벤트의 상태 갱신을 합친다. 편집 창 뒤의 투명 합성을 제거했다.
CLI 화면만 변경하므로 이번 개선을 위해 GNOME 재로그인이나 재부팅은 필요하지 않다.
로컬 모의 UI에서 지연 감소를 확인했으며 실제 Rocky/SSH/Ghostty의 체감은 별도 확인한다.

## RC34 화면 조회 속도 개선

`ala update --prerelease` 후 `ala`를 종료하고 다시 실행해 `0.1.0rc34`를 사용한다.
화면 관리의 사용자 왕복·Chrome 소유권·GNOME 출력 중복 조회를 줄이고 같은 요청 안의
독립 작업을 병렬 처리한다. 새로고침 중 다시 누르면 현재 조회를 유지하며 결과 옆에
소요 시간을 표시한다. 이 성능 변경은 기존 사이트·Chrome 프로필·GNOME 확장을 바꾸지
않는다. 캐시는 요청마다 폐기하며 실패·조회 불가·변경 전 검증을 생략하지 않는다.

## RC33 모든 출력의 대기 안내

`ala update --prerelease` → `ala --version`(`0.1.0rc33`) → `ala`에서 간편 설정을 실행한다.
안내 준비 선택이나 사이트 유무와 무관하게 출력별 대기 서비스가 등록된다. 이후 GNOME에서
한 번 로그아웃·로그인해 확장의 새 배치 검증을 로드한다. SSH 재접속과는 다르다.
초기화나 사이트 주소 삭제는 필요 없다. 정상 관리 창이 없는 연결 출력마다 독립 로컬
Chrome 안내를 유지하며 해당 출력의 실제 관리 창이 확인되면 안내만 닫는다.
사이트 자동 시작을 끈 출력에도 대기 안내를 표시하지만 현재 세션의 명시적인 수동 중지와
화면 변경·복구는 우선한다. 실제 Rocky/GNOME 패널 수용은 별도다.

## RC32 초기 설정 중 안내

`ala update --prerelease` 뒤 `ala --version`이 `0.1.0rc32` 이상인지 확인한다.
간편 설정의 **모니터별 안내 화면 준비**를 요청하면 Chrome과 그래픽 세션이 준비되는
시점부터 로컬 **기기 설정 중** 이미지를 표시하고, 모니터별 안내가 준비되면 넘겨준다.
이미 운영 중인 사이트를 초기화하거나 강제 재시작하지 않는다. 기존 대기 요청은 간편
설정에서 다시 요청해 현재 버전으로 이어갈 수 있다. RC31 확장이 이미 로드돼 있다면
이번 안내 기능만을 위해 추가 GNOME 재로그인을 요구하지 않는다.

## RC31 모니터 설정 사용

`ala update --prerelease`로 갱신하고 `ala --version`이 `0.1.0rc31` 이상인지 확인한다.
`ala`의 화면 관리 → **모니터 배치·해상도**를 연다. 기존 설치에서 기능 준비 안내가 나오면
**확장 갱신**을 선택한 뒤 GNOME에서 한 번 로그아웃·로그인한다. SSH를 다시 연결하는 것과
다르며 자동 로그아웃·GDM 재시작·재부팅은 하지 않는다.

세 대 이상·상하 배치, 출력별 해상도·배율과 사이트를 설정한다. 위치 교환은 드롭 시에만
편집값에 반영된다. 변경 검토·적용 뒤 30초 안에 화면을 확인하고 유지 또는 복원을 선택한다.
기본 선택인 **다음 로그인에도 유지**로 확정하면 ala 프로필을 저장하고 이후 GNOME 확장
세션에서 연결·지원 모드를 대조해 다시 적용한다. 실제 Rocky 수용은 별도로 기록한다.

## 최초 한 번 준비

새 도구를 설치하고 간편 설정으로 등록을 준비한 뒤 `u → 자동 운영`을 연다.

1. **최초 준비:** 별도 root 작업이 고정 버전·해시의 독립 Sigstore 검증기를 설치하고,
   현재 게시 배포의 서명·설치 manifest를 대조한다. GitHub 인증은 사용하지 않는다.
2. **화면 코드 적용:** 선택 대상만 명시적으로 전환한다. 현재 표시를 잠깐 중단할 수 있으므로
   점검 중에 실행한다. 기존 RC20은 schema1을 유지한 채 먼저 이 전환을 완료한다.
3. 실제 모니터·로그인·재부팅·코드 적용을 관찰한다. 자동 테스트를 이 확인으로 대신하지 않는다.
4. 수용 확인 스위치를 켜고 **자동 운영 켜기**를 선택한다.

```bash
ala update --bootstrap
ala update --policy
ala update --apply-runtime default
ala update --enable-auto --confirm-acceptance
```

최초 준비·명시적 코드 전환은 systemd 작업으로 접수하므로 SSH/TUI 종료와 독립한다.
서명 검증기는 별도 고정 바이너리여서 최초 다운로드 용량이 크다. 준비 실패·인터넷 장애에는
기존 화면을 유지하며 실제 검증 기록 없이 자동 운영을 켜지 않는다. 아직 게시하지 않은
개발 소스는 현재 공개 배포와 서명을 대조할 수 없으므로 준비 대기로 남는다.
서명 번들이 없는 공개 RC도 준비를 완료할 수 없다. RC21은 보호 환경과 태그 규칙을
설정한 뒤 공개 서명 파일을 검증했다. 실제 장비 수용 결과는 별도로 확인한다.

RC20에는 새 구성 스냅샷 지원이 없다. 이전 완료 전에는 다른 URL/schema2를 저장하지 않아
다음 장애 재시작을 보호한다. 이전이 끝난 뒤 다중 화면을 저장하고 간편 설정을 다시 적용한다.
기존 실행이 변경 가능한 `current` 경로만 가리켜 버전을 입증할 수 없으면 표시를 유지하고
전환을 대기한다. 이때는 점검 중 **화면 관리에서 중지 → 화면 코드 적용 → 시작 → 실제
모니터 수용** 순서로 이전한다. 중지 상태의 코드 선택만 끝난 결과는 실행 미검증이며,
시작·화면 확인을 마치기 전까지 무인 복구 완료로 취급하지 않는다.

## 운영 중 확인과 중지

```bash
ala update --check
ala update --status
ala update --policy
ala update --disable-auto
```

자동 운영 끄기는 다음 CLI/야간 실행을 중지한다. 현재 Chrome과 접수된 설치는 종료하지 않는다.
프론트 감시는 대상의 `frontend.enabled`로 별도 제어한다. 배포 실패의 명시 재시도는 화면 관리의
**배포 재시도**에서 선택 대상만 수행한다. 자동 코드 전환은 사용자가 중지한 창을 켜지 않는다.

CLI의 설치 버전·현재 명령 버전과 각 화면의 선택 버전·실제 실행 버전·후보를 따로 확인한다.
업데이트 진행 기록은 GitHub가 일시 중단돼도 로컬에서 조회할 수 있다.

## 검증·실패와 복원

자동 CLI 갱신과 최초 준비는 HTTPS·SHA-256·manifest에 더해 고정 저장소/tag-only
workflow의 Sigstore 번들 검증을 필수로 요구한다. 수동 다운로드 설치와 기존 수동
`ala update` 경로의 SHA-256·manifest 검사는 서명 검증과 별개다.
체크섬만을 서명으로 취급하지 않는다. 고정 검증기의 해시도 실행 전에 확인한다.
서명 workflow는 보호된 태그·리뷰 정책으로 운영하고 시험 장비부터 단계적으로 확대한다.

CLI 전환 후 검사 실패는 해당 작업이 변경한 포인터만 이전 검증 버전으로 되돌린다.
화면은 후보 시작 최대 90초, 안정 관측 60초, 실패 복원 90초를 사용한다. 잔여 야간 시간이
4분 미만이면 새 대상으로 진행하지 않는다. 하나 실패하면 나머지는 보류한다.
사이트 자체 장애만으로 코드가 고장났다고 판정하지 않는다.

시험 후보와 확정 선택을 분리하며, 전원 차단 뒤에는 마지막 확정 선택으로 시작한다.
수동 중지는 적용·복원보다 우선한다. 실행·확정·후보·복원 대상 release는 자동 삭제하지 않는다.
오래된 TUI에서 새 구성 형식을 이해하지 못하면 관리 화면을 종료하고 ala를 다시 실행한다.
