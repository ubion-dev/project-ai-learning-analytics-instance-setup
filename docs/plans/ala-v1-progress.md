# ala 공개판 진행 기록

## 상태 우선 TUI와 Bash 편의 기능

- 간편 설정·상태 확인·화면 관리·DID 빠른 점검·업데이트·자동 운영에서 상태와 다음 조치를 상단에 표시한다.
- 간편 설정의 Bash 옵션은 한 작업에만 기록한다. 고정 `ble.sh` 설치에 실패해도 이후 설정을 진행하고 최종 보고에 선택 기능 실패를 표시한다.
- Linux Bash 5.2 PTY에서 고정 배포 파일의 대화형 로드, 자동 제안·강조 설정, 기존 별칭·완성 정의, 비대화형 단일 출력을 확인했다. 로컬 설치 묶음에서 모듈 포함, SHA-256, 압축 해제 후 버전을 검증했다.
- Python 3.12 전체 회귀 1,231개와 하위 검사 56개가 통과했고 4개는 건너뛰었다. 80×24 GNOME 로그 버튼 보완을 포함한 최종 관련 회귀 47개와 하위 검사 31개도 통과했다.
- 다음은 시험 강의실 두 대의 TUI를 확인하고 일반 운영 계정 한 곳에서 Bash 옵션을 적용한 뒤, 실제 SSH 로그인과 재부팅 후 DID 표시를 확인하는 것이다.

## DID 빠른 점검

- 기본 TUI에 읽기 전용 빠른 점검을 추가했다. GNOME 세션·관리 Chrome·창 배치·사이트 순으로 첫 조치와 다음 단계를 표시한다.
- 선택 대상의 현재 부팅 로그와 기존 화면 관리로 이어진다. 명시 확인 후 시작·재시작을 요청하고 같은 대상을 재검사한다. GNOME 로그인 로그는 GDM 단서만 요약한다.
- Python 3.12 관련 회귀 131개와 diff 검사를 통과했다. 80×24 모의 TUI에서 두 번째 대상 선택·로그·시작·재시작·재점검을 확인했다.
- 다음은 시험 강의실의 실제 Rocky 재부팅 이후 DID 미표시 상황에서 시작 로그와 복구 동선을 확인하는 것이다.

## 화면 관리의 DID 모니터 이동

- 화면 관리의 선택 DID를 현재 출력에서 빈 출력으로 드래그하고, DID·사이트·출력 방향을 확인한 뒤 적용하는 흐름을 구현했다. 작은 터미널은 출력 행을 사용한다. 기존 설정 편집과 키보드 제어는 유지한다.

- URL=None을 외부 요청 없는 내부 HTML 안내 모드로 지원한다. 실제 로컬 문서 로드 근거를 `waiting_configuration`/`local_page_ready`로 표시하며 사이트 정상과 구분한다. root 관리 자동 시작 등록은 설정 적용 전후에 좁게 동기화한다. 기존 실행·수동 중지·꺼짐과 미관리 파일을 보존한다.
- 모니터 식별 버튼과 GNOME47/49의 비포커스10초 표지를 추가했다. protocol1의 capabilities로 구버전을 구분하고 번호는 논리 출력 ID순으로 TUI·안내·표지에 연결한다. 연결 변경·잠금·확장 종료 시 표지를 정리한다.
- 목적 출력에 전체화면 DID 하나가 있으면 두 화면 교환 확인을 제공한다. 서버의 영속 작업 하나가 두 출력만 교환하며 committed/desired 코드와 다른 설정은 보존한다. commit 결정 전은 이전 배정 복구, 결정 후는 새 배정 정리로 처리한다. lease만료·부팅 후에도 미완료 journal의 격리를 유지하고 수동 중지·조회 불가·부분 예약·복구 실패를 구분한다.
- 실제 leaf 제어·환경 pin·사용자 구성 로드·Chrome 종료 후조건을 잇는 모의 통합을 포함했다. 등록 충돌의 실제 이유와 조치를 숨기지 않으며 불완전 초기 준비의 로그인 fence는 유지한다. 영속 교환 결과에 맞춰 TUI 접수/완료/복구 상태를 갱신한다.
- Python3.12 전체 회귀 1514 passed, 4 skipped, 56 subtests를 통과했다. 이후 좁은 UI 추적 정리와80×24 대상 행 노출 보완 후 관련71개를 통과했다. Bash/Node 구문, 공개 데이터·비밀정보, 배포88개 manifest 해시·새 모듈·기능 metadata 포함 검증을 통과했다.

## 모니터 중심 화면 관리 개편

- 화면 관리의 표시 대상 표와 메인 운영 버튼을 제거했다. 모니터 클릭·방향키·Enter로 해당 DID 설정을 열고, 시작·중지·재시작·페이지 새로고침·로그·배포 재시도·교환 복구는 설정 창 안에서 사용한다. 메인에는 모니터 식별과 다시 조회만 유지한다.
- 연결 해제·미배정·출력 확인 불가 대상은 접힌 별도 영역에서 계속 열 수 있고 화면 추가도 제공한다. 한 모니터에 여러 분할 DID가 있으면 명시적으로 대상을 선택한다. 빈 확정 출력은 출력이 미리 선택된 추가 창만 열며 저장 전에는 변경하지 않는다.
- 모니터는 26×7 셀의 테두리·받침대가 있는 고정 모양이다. 해상도는 문자로 표시하고 공간이 부족하면 줄바꿈·스크롤한다. 논리 출력 ID순 번호는 식별 기능과 일치하며, 키보드 선택에 따라 상단 상태도 같은 DID를 따라간다.
- 클릭과 2셀 이상 드래그를 구분하고 취소·무효 드래그가 설정 열기로 이어지지 않게 했다. 기존 단일 이동·영속 교환 작업, 승인 전 무변경, 승인 뒤 구성·출력·상대 재검사와 적용 스냅샷 고정을 보존한다.
- 운영 가능 조건을 대상별 공통 함수로 분리했다. 열린 설정 창의 DID ID와 적용 구성 스냅샷을 고정하고, 주기 조회에서도 편집 값과 포커스를 보존한다. 미저장 편집 중에는 로그 외 운영을 차단한다. 빠른 점검에서 같은 DID의 설정 창으로 연결하되, 느린 조회를 기다리다 다른 화면으로 이동하면 뒤늦게 창을 열지 않는다.
- Python 3.12 전체 회귀는 1563 passed, 4 skipped, 56 subtests passed였다. 이후 초기 포커스·파스텔 접힘/스크롤 색·키보드 선택 상태를 보완한 최종 코드에서 지도·드래그·화면 관리·빠른 점검 연결 회귀 92개를 통과했다. 합성 80×24·120×36 컬러 렌더링으로 고정 모양, 운영 메뉴 노출과 저장/닫기 버튼을 확인했다.
- 변경 파일 공개 데이터·비밀정보 검사, diff 검사와 고정 wheel을 사용하는 로컬 배포 묶음을 검증했다. 네 TUI 모듈이 묶음에 최종 소스와 동일하게 포함된다. 실제 Rocky 장비 변경·수용과 PR·태그·새 프리릴리스는 수행하지 않았으며 게시된 릴리스는 유지한다.
