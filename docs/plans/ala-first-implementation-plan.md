# 장비별 설치 준비와 분석 서버 연결의 첫 구현 계획

상태: 사용자가 개발 보류를 해제해 코드 구현을 시작했다. 실제 장비 적용·원격 게시 승인은 별도다. [상위 설계](ala-install-operations-plan.md)의 합의를 실제 개발 순서와 완료 조건으로 나눈다.

## 구현 현황 — 모니터 설정 기반

첫 코드 변경은 추가 합의한 모니터 설정의 읽기 전용 기반이다. `ala display modes --json`으로 출력별 모드 ID·해상도·주사율·권장/지원 배율과 편집 템플릿을 조회하고, `ala display plan FILE --json`으로 최신 상태에 대해 배치를 검사한다. 이 명령은 설치된 과거 버전에는 없다.

활성 출력 전체를 명시하며 좌표·모드·배율만 편집한다. 주 모니터·회전·사이트 배정은 보존한다. 출력 연결이나 모드 정보가 달라졌으면 재조회를 요구하며, 출력별 미지원 모드/배율·공통 배율 제약·겹침·화면 가장자리의 단절을 거부한다. 복제 출력은 조회만 제공한다. 지원 정보를 완전히 해석하지 못해도 기존 창 배치 조회를 차단하지 않는다.

조회·계획 결과는 로컬 검사이며 `apply_supported: false`, `backend_verified: false`로 구분한다. `trial`·`apply`·`trial-status`·`confirm`·`revert`·`recover`와 화면 관리의 **모니터 배치·해상도** 편집 화면을 연결했다. systemd 실행기가 공통 변경 잠금을 소유한 채 현재 GNOME 세션에 적용하고 실제 출력과 compositor 영역을 대조한 뒤 30초 동안 확정 응답을 기다린다. 응답 부재·취소는 복원을 요청하며 실행기 종료 시 `ExecStopPost`가 복구를 시도한다. 남은 복구 기록은 다른 ala 변경과 설치·갱신을 차단한다.

`trial`은 현재 세션에만 적용한다. `apply` 또는 기본 선택인 **다음 로그인에도 유지**로 확정하면 ala 자체 프로필을 저장한다. GNOME 고유 영구 확인 창을 우회하거나 `monitors.xml`을 직접 쓰지 않는다. 새 GNOME 확장 세션에서 연결 정보·계정·모드·배율·주 모니터·회전·좌표 방식을 대조하고 같은 실행기로 저장 배치를 다시 적용한다. 세션 내 수동 변경을 주기적으로 되돌리지 않으며 자동 복원 끄기·재시도를 제공한다. 드래그 중에는 교환 상대를 강조만 하고 드롭 때만 편집값을 바꾼다. 해상도 변경으로 미지원이 된 배율은 직접 다시 선택한다. 기본 TUI 지도의 기존 드래그는 DID 배정이고 OS 배치 편집과 구분한다. 실제 Rocky 수용은 별도다.

## 이번 개발의 끝점

운영자가 Mac에서 표시 담당 또는 분석·표시 담당 PC의 설정을 준비하고, 고정 주소·SSH가 준비된 Rocky에서 해당 장비의 설정과 필요한 변경을 검토한 뒤 기존 ala 설치 작업을 실행한다. 지정 분석 서버 배포물이 제공되면 최초 설치·등록·준비 상태 확인까지 연결한다. 배포물 또는 연결 계약이 아직 없으면 환경 준비 완료와 분석 서버 준비 대기를 나누어 표시한다.

기존 CLI·TUI와 환경·화면·업데이트·복구 기능은 유지한다. 최초 네트워크 도우미·네트워크 자동 변경·자동 재부팅·골든 이미지 제작·회사 중앙 관리 서비스는 이 첫 구현과 분리한다. 각각의 후속 설계는 상위 계획에 남긴다. 공통 이미지에서도 같은 장비별 설정 절차를 재사용할 수 있게 한다.

## 재사용할 구현과 추가할 경계

| 현재 구현 | 사용 또는 확장 방향 |
| --- | --- |
| `ala/config.py`의 schema 1/2 | 기존 장비 환경·화면 구성과 유효성 검사를 유지 |
| `ala config import`, `config edit` | 기존 구성 입력과 편집 경로 유지 |
| `ala config show --json` | 응답 객체와 실제 구성 데이터를 구분. 내보낸 파일을 다시 읽을 수 있는 전용 경로 추가 검토 |
| `ala/service.py`의 구성 대조·원자 저장 | 새 입력도 기존 구성 보존·조회 후 변경 감지·실행 중 변경 차단을 통과 |
| `ala/jobs.py`의 작업 ID·고정 worker·공통 잠금 | 장비 내부 설치 실행·재접속 조회의 기반으로 재사용 |
| 기존 installer와 서명·manifest 검사 | 분석 서비스 배포 규약과 구분해 검증 계약 유지 |

단일 PC의 기존 Config에 기관 전체 목록이나 SSH 접속 정보를 섞지 않는다. Mac에서 관리하는 장비 목록, 한 PC에 적용하는 환경 구성, 분석 서버의 배포 정보와 비밀 전달 경로를 구분한다. 실제 파일명·명령 이름은 구현 시 기존 명령 체계에 맞춰 확정한다.

## 1단계 — 장비별 설정 준비·검증·내보내기

### 입력과 결과

- 설치 대상의 안정적인 식별자, 장비 역할, 기존 일반 사용자, 화면별 URL·배정과 분석 설정을 데이터로 표현한다.
- `표시 담당`과 `분석·표시 담당`을 하드웨어 모델 이름과 분리한다. 관리 기능은 두 역할 모두 필요하며 분석 실행 범위만 다르다.
- 장비 목록을 검증하고 대상별 구성 파일을 만든다. 기존 ala에서 이해하는 환경 구성과 신규 역할·분석 배포 정보의 버전을 구분한다.
- 기존 구성 내보내기는 실행 응답을 재입력하는 우회가 아니라, 다시 검증·가져올 수 있는 명시적 구성 데이터로 제공한다.
- 비밀은 구성 템플릿·공통 이미지·생성 결과에 포함하지 않는다. 인증에 필요한 참조와 실제 자격증명은 별도 경계로 둔다.

### 완료 조건

- Mac에서 Rocky 전용 명령·권한 승격 없이 파일 준비와 읽기 전용 검증을 수행할 수 있다.
- 기존 schema 1/2 입력을 계속 처리하고 내보내기→가져오기에서 의도한 구성 값이 보존된다.
- 중복 장비 ID·지원하지 않는 역할·중복 화면 ID·유효하지 않은 구성·잘못된 버전을 거부한다.
- 출력 경로 이탈과 기존 파일의 무단 덮어쓰기를 막고, 실패한 입력으로 정상 생성물을 손상하지 않는다.
- 실제 장비·주소·고객 정보 없이 합성 입력으로 역할별 결과와 오류 경계를 확인한다.

이 단계는 설치 준비 도구다. SSH 원격 일괄 실행·장비 등록 서버·분석 앱 설치를 제공했다고 표시하지 않는다.

## 2단계 — Rocky에서 대상 설정 검토·적용

- 전달받은 한 장비의 설정과 현재 저장 구성·출력을 대조한다. 다른 PC의 설정을 잘못 선택할 수 있으므로 대상 식별과 적용 내용을 표시하고 명시적 검토를 거친다.
- 조회·계획은 구성이나 백업·서비스를 변경하지 않는다. 실제 저장·적용은 기존 권한 검사·공통 변경 잠금·구성 변경 감지를 유지한다.
- 기존 화면·프로필·일반 사용자·수동 중지와 관리 밖 구성을 임의 인수하거나 초기화하지 않는다. 출력 정보가 확인되지 않으면 정확한 배치 성공으로 표시하지 않는다.
- 최초 저장·재실행·취소·설정 충돌·작업 중복·SSH 종료와 재접속을 기존 영속 작업 모델로 처리한다.
- 고정 주소는 현장에서 수동 설정한 결과를 읽기 전용으로 확인하며 자동 변경하지 않는다.

### 완료 조건

기존 CLI·TUI와 구성 보존 회귀가 통과하고, 합성 장비에서 두 역할의 계획·명시 적용·동일 설정 재실행·구성 충돌·재접속 결과가 의도대로 구분된다. 실제 Rocky의 재부팅·화면·GPU 수용은 별도 단계로 남긴다.

## 3단계 — 지정 분석 서버의 최초 배포 연결

분석 서버 저장소가 버전이 고정된 배포물과 다음 계약을 제공해야 실제 설치까지 완료할 수 있다.

- 역할별 서비스 구성과 이미지 digest, 허용된 Compose 구성
- 호스트·Docker·GPU·모델·데이터 형식의 호환 요구
- 설정 스키마와 비밀 전달 경로
- 시작·중지·등록·준비 상태·실행 버전의 확인 방법
- 데이터 보존·이전·업데이트 실패 복구 조건
- 관리 기능이 분석 서비스의 중지·교체 중에도 유지되는 실행 경계

임의의 Compose 파일·명령을 root로 받아 실행하는 범용 배포기로 만들지 않는다. 검증한 전용 배포물과 허용된 설정만 처리한다. 서명·무결성 검증을 다운로드 인증과 구분하고 어느 쪽도 생략하지 않는다. 정확한 접근 방식과 발행자 검증은 비공개 배포 설계에서 확정한다.

### 완료 조건

검증된 시험용 배포물로 다운로드·검증·등록·준비 판정과 접속 종료 후 결과 조회를 확인한다. 배포물 부재·인증 실패·검증 실패·준비 실패·복원 불가를 구분하며, 설정·모델·데이터 보존을 확인한다. 이 결과를 실제 STT·영상 분석 성능 검증과 혼동하지 않는다.

## 4단계 — 실제 장비 한 대에서 처음부터 끝까지 수용

OS·고정 주소·SSH의 수동 준비 → Mac의 설정 생성 → 설정 전달과 검토 → 환경 설치 → 화면 표시 → 분석 서버 설치·준비 → 운영자 재부팅 → 재접속과 실제 표시·분석 결과 확인 순으로 검증한다.

고사양 PC의 Chrome·STT·CCTV 동시 부하를 측정하고 분석 역할의 실제 배치를 확정한다. 표시 담당 장비도 별도로 검사한다. 실제 입력과 화면을 확인하지 않은 상태를 최종 서비스 준비 완료로 판정하지 않는다.

## 이번 계획의 외부 의존성과 다음 결정

### 개발 전 추가 요구 — 모니터 확인·배치·사이트 설정

사용자가 코드 개발 시작을 보류한 상태에서 연결 모니터의 직관적 표시, 드래그앤드롭으로 OS의 2차원 모니터 배치 변경과 모니터별 사이트 설정을 추가 요청했다. 두 대와 좌우 교환으로 한정했던 해석은 사용자 정정에 따라 폐기했다. 시안 승인 후 개발 보류를 해제했으며 위 구현 현황과 아래 목표 요구를 구분한다. 실제 장비 변경은 아직 수행하지 않는다.

- Rocky의 실제 GNOME 출력 정보를 조회해 연결 상태·식별 번호·현재 배치를 표시한다. Mac에서 미리 준비한 배정과 실제 장비에서 확인한 연결을 구분한다.
- 모니터 식별 표지를 실제 화면에 표시해 설정 화면의 모니터와 현장 패널을 대응시킨다. 번호를 좌우 위치와 같은 뜻으로 쓰지 않는다.
- 모니터를 선택해 사이트 주소를 지정하고, 적용 전 현재 값과 변경값을 비교한다. 사이트 입력·저장·현재 실행 적용과 재로그인/재부팅 복원을 구분해 확인한다.
- 모니터 카드에는 현재 표시 사이트와 설정 변경 대기·연결 해제·조회 불가 등 상태를 함께 표시한다. 연결되지 않은 출력이나 불명확한 배정을 정상 연결처럼 그리지 않는다.
- 기존 모니터 지도·식별·사이트 편집·DID 이동/교환 구현을 재사용하고 완료된 기능을 반복 구현하지 않는다.
- OS가 인식하는 모니터 배치는 연결된 출력 수에 따라 표현한다. 세 대 이상과 좌우·상하·여러 줄 구성을 지원하는 2차원 편집을 요구한다. 모니터를 직접 드래그하고 인접 화면의 경계에 맞춰 놓는 흐름을 기본으로 하며, 현재 코드의 DID/사이트 배정 이동·교환으로 이 요구를 대체하지 않는다. 현재 GNOME 좌표 편집은 미구현이다. 이후 사용자가 모니터별 해상도와 비율 조절을 추가 요청했으며 아래 항목에서 구체화한다. 회전 편집은 아직 요청 범위에 포함하지 않는다.
- 모니터별 해상도를 선택할 수 있도록 한다. 실제 연결된 출력에서 지원하는 모드를 조회해 선택지를 제공하고, 현재 적용값과 편집값을 구분하는 방향으로 설계한다. 지원하지 않는 모드를 임의 생성하거나 요청한 값만으로 적용 성공을 판정하지 않는다. 현재는 요구사항이며 실제 기능 제공을 뜻하지 않는다.
- 사용자는 `비율`을 OS의 화면 배율이라고 확인했다. 가로세로 비율 편집과 구분한다. 해상도·배율은 공통 고정 목록이 아니라 실제 출력별 지원 모드와 모드별 지원 배율을 조회해 제공한다. 해상도를 바꾸면 배율 선택지도 다시 검증하며, 기존 배율이 지원되지 않을 때 임의로 강제 적용하지 않고 해당 상태와 지원 값을 표시한다.
- 모니터의 사양뿐 아니라 현재 GNOME 세션·백엔드의 제약을 함께 확인한다. GNOME 47·49의 DisplayConfig 원문에서 모드별 지원/권장 배율과 공통 배율 요구 속성을 확인했다. 공통 배율이 필요한 환경에서는 독립 배율을 제공할 수 있다고 표시하지 않으며, 지원 여부를 확인하지 못하면 임의 목록으로 대체하지 않는다.
- 해상도·배율 변경에 따라 OS의 논리 화면 크기와 다른 출력과의 겹침이 달라질 수 있으므로 배치 미리보기·검증·실제 수용 조건을 함께 구체화한다. 현재 시안의 동일 크기 예시를 실제 장비의 크기 규칙으로 사용하지 않는다. 기존 주사율·회전 등 요청하지 않은 설정을 몰래 바꾸지 않고, 적용 직전 출력 연결·지원 모드·구성 세대가 바뀌면 다시 검토한다.
- 다른 모니터 위에 드롭하면 두 모니터의 OS 배치 위치를 서로 교환한다. 드래그 중인 모니터만 포인터를 따라가고, 상대 모니터는 원래 위치에 유지한 채 교환 대상 표시만 한다. 드롭을 완료하기 전에는 상대 모니터 이동·자리 교환·자동 재배치를 하지 않는다. 빈 공간 드롭은 한 모니터의 이동으로 구분한다. 이는 사이트 배정 교환이 아니며 모니터 식별·사이트·프로필·시작/중지 상태는 각 출력에 유지한다.
- 실제 출력의 해상도·논리 크기가 다를 수 있으므로 위치 교환 후 다른 출력과의 겹침·허용되지 않는 배치를 별도로 검증해야 한다. 한 출력의 크기에 맞춰 나머지 출력의 해상도나 사이트를 임의 변경하지 않는다. 추가 재배치가 필요하면 적용 전에 검토하도록 한다.
- 현재 배치와 적용 예정 배치를 나란히 확인하고, 실제 모니터 식별 표지와 대응시킨다. 식별 번호를 위치 순서에 따라 재지정하지 않는다. 사용자가 배치 변경 시 사이트는 기존 모니터에 유지하는 정책을 선택했다. 출력 좌표만 바꾸는 작업에서는 DID·사이트의 기존 출력 배정과 자동 시작·수동 중지 상태를 보존하고, 사이트 교환은 별도 명시 작업으로 제공한다.
- OS 배치 변경은 초기 조회·편집만으로 실행하지 않는다. 적용 전 그래픽 세션·출력 연결·현재 배치를 다시 대조하고, 중복 변경은 기존 공통 잠금으로 막는 방향을 설계한다. 확인할 수 없는 세션을 임의 선택하거나 GDM·다른 사용자 세션을 강제 재시작하지 않는다.
- 적용 뒤 실제 OS 배치와 관리 Chrome의 출력 배치를 다시 확인한다. 임시 적용 후 유지 확인·미확인 시 이전 배치 복원 절차를 요구사항으로 검토하되, GNOME의 지원 방식과 실제 Rocky에서의 복원 검증 전에는 제공되는 기능으로 표시하지 않는다. 저장과 재로그인·재부팅 후 유지도 실제 장비 수용에서 확인한다.

OS 배치 변경과 사이트 배정을 별도 요구로 포함한다. `모니터 1·사이트 A / 모니터 2·사이트 B`에서 OS 좌우 순서를 바꾸면 `모니터 2·사이트 B / 모니터 1·사이트 A`로 표시하는 것을 수용 시나리오에 포함한다. 출력 연결이 바뀌거나 기존 출력을 확실히 대응시킬 수 없으면 좌우 위치나 번호만으로 사이트를 임의 재배정하지 않는다. 구체적인 화면 흐름·복원 방식·구현 우선순위의 후속 검토와 사용자의 개발 보류 요청을 유지한다.

대화에서 검토할 독립 시안의 동선은 `모니터 클릭으로 사이트 편집 / 다른 모니터로 드롭해 위치 교환 / 빈 곳으로 드롭해 이동 → 변경 전후 도식 검토 → 시안 적용`으로 수정했다. 예시는 두 대·세 대·네 대를 제공하되 실제 제품의 출력 수를 이 예시 수로 고정하지 않는다. 모니터 식별·편집 취소·영역 밖 또는 안착할 수 없는 드롭의 취소와 키보드 대체 동선을 포함한다. 이는 실제 터미널 화면이나 GNOME 연동 구현이 아니며, 실제 장비 조회·변경을 하지 않는다. 터미널 크기·키보드·임시 적용 후 복원은 후속 설계와 실제 구현 검증 항목으로 남긴다.

해상도·배율 시안은 출력마다 서로 다른 합성 지원 모드와 모드별 배율 목록을 사용한다. 해상도 변경으로 기존 배율이 유효하지 않으면 배율을 선택하기 전까지 적용할 수 없으며, 그동안 그림은 권장 배율 기준의 미리보기임을 표시한다. 선택한 해상도와 배율에 따라 논리 화면 크기를 달리 그리고 기존 좌표를 임의 재배치하지 않는다. 크기 변경의 겹침은 별도로 표시하며 드래그로 해소한 뒤 검토할 수 있게 한다. 서로 다른 크기의 두 출력은 배치 위치 교환 후 겹침을 검사하며, 다른 출력의 위치나 해상도는 몰래 변경하지 않는다. 시안의 합성 지원 값과 크기 계산은 실제 GNOME 지원 목록 조회·배치 검증의 구현으로 간주하지 않는다.

- 분석 서버 저장소의 실행 가능한 서비스·배포물·연동 계약이 아직 확인되지 않았으므로 3단계의 실제 완료에는 해당 산출물이 필요하다.
- 비공개 파일 배포·컨테이너 레지스트리·기관/장비 등록·자격증명 갱신 방식은 미확정이다. 현행 공개 저장소와 업데이트 경로를 먼저 끊지 않는다.
- 교내 어드민 백엔드 담당자와 API·인증·작업 결과·재시도 계약을 맞춘다. [인계 가이드](../device-management-integration.md)는 초안이며 실제 전송·협의 완료와 구분한다.
- 단계별 구현·모의 검증·실제 장비 수용 결과와 다음 행동을 진행 기록에 남긴다. 전체 합의가 필요한 정책·네트워크·실제 장비 변경을 초기 파일 준비 구현에 끼워 넣지 않는다.
