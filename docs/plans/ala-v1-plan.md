# ala 공개판 계획

## 제공 범위

Rocky Linux 10 x86_64 + GNOME/GDM 환경에서 기존 일반 사용자를 대상으로 설치·설정·검사·Chrome 표시를 관리한다.
Python 3.12, argparse, Textual과 내부 Bash 모듈을 사용한다.
OS 설치·파티션·애플리케이션 배포·DB 운영·DID 패널 제어는 제외한다.

## 유지할 계약

- 현재 상태 조사 → 변경 계획 → 적용 → 재검사. 이미 정상인 패키지와 동일 설정은 유지한다.
- plan/check/status는 설치·서비스 변경·설정·백업 생성을 하지 않는다.
- root 고정 실행기와 systemd 작업은 SSH 종료와 독립한다. 설치·갱신은 같은 잠금을 사용한다.
- 기존 구성·Chrome 프로필·Docker 설정을 보존한다. 실행 중 서비스 강제 재시작이나 자동 재부팅은 하지 않는다.
- 새 표시 프로필, 일반 사용자 Chrome, GNOME 자동 로그인·잠금/절전 방지, F11 전체화면을 사용한다.
- 표시용 Chrome만 --password-store=basic을 사용한다. 이 프로필에 인증정보를 저장하지 않는다.
- setup은 전체 OS 업데이트를 하지 않는다. prepare는 별도 최초 공식 OS 준비와 명시적 재부팅 검증이다.
- NVIDIA 및 공식 드라이버 누락을 조사한다. 미지원·초기화 실패를 자동 패키지 삭제/보안 우회로 해결하지 않는다.
- 네트워크 진단은 연결을 변경하지 않는다. 외부 probe는 명시 옵션이며 호스트 통신과 Wi-Fi 통신을 구분한다.
- 실제 화면 관찰을 프로세스 인자·모의 테스트로 대체하지 않는다.

## 공개 배포 준비

1. 공개 코드·문서·테스트를 유지하고, 원래 개발 이력은 민감한 내용을 정리해 작성자·날짜·병합 관계를 보존한 채 연결한다.
2. 인증 없는 HTTPS 다운로드·설치·수동 갱신 절차를 문서화한다.
3. 기존 버전은 덮어쓰지 않고 새 후보를 빌드·검증·게시한다.
4. CPU/GPU 실기기 수용 후 정식 버전을 판단한다.

## 후속 제안 — 아직 미구현

주기적 업데이트 타이머, 배포 서명 검증, 단계적 배포, 장비 상태 보고는 별도 구현 대상이다.
공개 다운로드가 가능하다는 사실을 자동 업데이트가 구현되었다는 의미로 설명하지 않는다.

## 검증

읽기 전용·멱등성·권한 분리·설치 잠금·실행 기록·GPU/네트워크 진단·TUI·배포 설치 회귀를 유지한다.
실제 장비에서 첫 적용 → 재실행 → SSH 재접속 → 재부팅 → 화면·GPU 수용을 별도로 수행한다.

## ALA-13 — 목적 중심 첫 화면과 순서형 설정

- 첫 화면은 처음 설정/현재 설정 보완, 서버 상태 확인, 화면 관리, 고급 설정 네 진입점으로 줄인다.
- 순서형 설정: 기존 계정 확인 → 바탕화면/DID 선택 → 필요한 변경 요약 → 명시적 설정 시작 → 진행/다음 행동.
- sudo는 시작 동선에서 처리하고 암호는 sudo가 직접 받는다. 기존 고급 구성·OS 준비·실행 기록은 고급 설정 아래 유지한다.
- 저장된 선택 옵션을 보존하며 계획 판정·구성 변경 감지·단일 작업·백그라운드 실행 계약을 재사용한다. 사용자에게 plan/apply 개념을 요구하지 않는다.
- 80×24 키보드 흐름, 취소/실패/중복/계획 불일치/재접속을 headless 테스트한다. 기존 CLI/설치 엔진 회귀도 유지한다. RC4를 덮어쓰지 않고 새 RC5로 준비한다.

## ALA-14 — 새 버전 안내·명시적 자체 갱신

- 시작 화면에서 비동기 읽기 전용 업데이트 조회. 실패해도 환경 관리를 막지 않는다.
- ala update --check [--json], ala update [--prerelease]. 기본은 정식판, 시험판은 명시 선택. 버전 숫자 비교로 다운그레이드 방지.
- 공개 GitHub API와 고정 저장소 자산만 사용하며 인증정보를 요구/저장하지 않는다. HTTPS와 SHA-256·manifest 검증. 이는 서명 검증과 다르다.
- root 고정 실행기가 systemd 작업으로 갱신하여 SSH 종료와 분리한다. 기존 installer의 잠금·원자적 current 전환·구성 보존을 재사용한다.
- RC5는 불변. 기능 포함 버전으로 최초 수동 갱신 필요. 자동 적용·정기 타이머는 범위 밖.

## ALA-15 — 가독성·차단 원인 우선 화면

- 차단 상태와 재부팅 등 적용 대기를 분리한다. 차단 패키지·실제 상태·다음 조치를 숨기지 않는다.
- 차분한 색상, 상태 카드, 명확한 포커스, 접는 상세 내역으로 정보 밀도를 줄인다. 80×24에서도 키보드로 접근 가능해야 한다.
- Podman 차단은 Docker 공식 RHEL 설치 안내에 근거해 유지하며 자동 삭제하지 않는다. 기존 일반 사용자/root 컨테이너·볼륨 점검 절차를 안내한다.
- 모의 Podman 화면·정상 화면을 렌더링하고 키보드·회귀 테스트 후 RC7 후보로 제공한다.

## ALA-16 — 단계별 집중형 화면

- 사용자 선택: 가운데 작업 메뉴, 한 화면에 한 작업. 기존 왼쪽 고정 메뉴를 제거한다.
- 홈은 작업 이름+설명 목록, 설정은 계정/화면/확인의 진행 표시와 고정된 이전/다음 버튼을 사용한다.
- Esc/상단 홈으로 언제든 작업 목록에 돌아가며, 상세 화면으로 전환하면 해당 내용에 포커스를 둔다.
- 80×24/120×36, 크기 변경, 차단/정상/작업 진행, 키보드와 무색 터미널을 검증한다.
- 설치 엔진·명시적 적용·단일 변경 작업·구성 보존 계약 유지. RC8 후보로 준비한다.
