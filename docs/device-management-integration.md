# 교내 관리자 화면과 장비·분석 서버 연동 가이드 초안

이 문서는 설계 인터뷰의 합의와 후속 제안을 구분한 인계용 초안이다. API 구현·원격 연동·실기기 검증 완료를 의미하지 않는다. 실제 기관의 접속 정보·계정·장비 목록은 포함하지 않는다.

## 역할

| 구성요소 | 책임 |
| --- | --- |
| ala | 기존 OS 환경 준비·Docker/GPU 준비·Chrome 화면 관리·점검·업데이트·복구 기능 유지 |
| 장비·분석 서버 | 별도 분석 서버 저장소에서 관리 API와 카메라 제어, 음성 수신·STT·영상 분석을 구현 |
| 교내 어드민 백엔드 | 관리자의 권한 확인, 대상 선택, 관리 API 요청과 결과 표시 연동 |
| 회사 공통 관리 서비스 | 향후 조직 간 버전·정책·적용 결과 관리. 교내 운영의 필수 온라인 의존성으로 두지 않음 |

기존 ala의 호스트 변경 기능과 같은 작업은 고정된 공통 실행 경로를 재사용하는 방향으로 설계한다. 관리 API를 두 저장소에서 중복 구현하거나 각자 Compose·Chrome·패키지를 변경하지 않는다. 분석 서버의 API 제공과 호스트 변경 권한은 구분한다. 구체적인 호출 인터페이스는 미확정이다.

## 어드민 담당자와 확인할 요청 경로

관리자 브라우저 → 교내 어드민 백엔드 → 대상 PC의 관리 API를 기본 제안으로 한다. 사용자는 이 방향을 허용했으나, 어드민 담당자와의 연동 합의·기관 내부 통신 허용 여부는 별도로 확인해야 한다. IP 등록만으로 연결 가능성이나 제어 권한이 확인된 것으로 취급하지 않는다.

제어 범위는 PC·서비스 운영과 카메라 제어다. 물리 DID 패널의 전원·입력·밝기 제어는 현재 합의 범위에 포함하지 않는다. 관리자 화면에서 원격 셸이나 임의 스크립트를 실행하는 API는 제공하지 않는다.

## 요청·상태 계약 제안

- 조회와 변경을 구분하고 조회 요청은 장비 설정을 변경하지 않는다.
- 조직·장비·작업별 권한을 검사한다. 인증 방식과 자격증명 발급·갱신 방법은 후속 설계에서 정한다. 관리자 화면에 권한 있는 장비 자격증명을 전달하지 않는다.
- 지원 기능·API 버전·실제 실행 버전·상태 조회 시각을 제공한다. 연결 불가·정보 오래됨·기능 미지원·작업 실패를 정상 상태와 구분한다.
- 긴 작업은 작업 식별자로 접수와 완료를 구분한다. 화면 종료나 요청 연결 단절로 이미 접수된 작업을 중단하지 않는다.
- 재시도에 따른 중복 변경을 방지하고, 같은 자원에 대한 CLI·API·업데이트 작업은 공통 변경 잠금과 구성 대조 규칙을 따른다.
- 변경 전 확인한 대상과 설정이 달라지면 다시 검토하도록 한다. 실제 변경이 끝나면 결과 상태를 재검사한다.
- 로그와 작업 결과에는 비밀·전체 환경 변수·실제 인증 요청 내용을 담지 않는다.

## 서비스·데이터 경계

분석 서비스는 컨테이너 이미지와 Compose 구성으로 배포한다. 설정·모델·분석 결과·저장 데이터는 서비스 교체와 분리해 보존한다. 데이터 삭제는 별도 명시 작업이며 데이터 형식 변경의 이전·복구 조건을 배포물에 포함해야 한다.

분석 서비스를 중지·교체하거나 분석 프로세스가 실패해도 관리·복구 요청을 받을 실행 경로가 필요하다. 관리 기능의 실행·갱신 단위를 분석 서비스와 어떻게 분리할지는 후속 설계에서 확정한다.

외부 회사 서비스와 연결되지 않아도 교내 관리자 화면과 현장 ala에서 기관 내부의 상태 조회·허용된 운영을 계속 제공한다. 외부 연결 복구 후에는 과거 명령을 무조건 재실행하지 않도록 현재 상태와 정책을 대조하는 규약이 필요하다.

## 업데이트 정책과 미결정 사항

기관에 우선 승인·유예 기회를 주고, 사전 합의한 기한 이후 허용 점검 시간에 자동 적용하는 원칙은 [ADR 0001](adr/0001-update-approval-deadline.md)을 따른다. 대상별 적용 조건과 긴급 중지는 유지한다. 재부팅을 포함한 실제 장비 변경은 기존 보호 계약과 명시적 허용 조건을 충족해야 한다.

실제 URL·요청/응답 스키마·인증·포트·호환 버전·작업 재시도 규약·유예 기간·점검 시간·초기 설치 연결 방식은 미결정이다. 구현 전에 분석 서버 담당자와 어드민 백엔드 담당자가 확인하고 계약을 확정해야 한다.
