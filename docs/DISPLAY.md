# 화면과 부팅 관리

`ala`의 화면 관리 탭은 출력 배치도, 관리 대상, 선택 대상의 제어·상태를 분리한다.
물리 출력 행은 Linux DRM이 감지한 커넥터 연결 상태를 표시한다. 배치도와 출력 선택
목록은 GNOME이 확인한 활성 논리 화면을 사용한다. 복제 출력은 하나의 논리 화면으로
다룬다. 기본 대상은 활성 논리 화면이 하나일 때 자동 선택한다. 지정 출력이 연결
해제되면 설정을 보존하고 배치를 대기한다. `ala display list --json`에서 두 관측을 확인한다.

## 설정과 제어

대상마다 ID·사이트·출력 연결자·자동 시작·배치를 저장한다. 정상 운영은 논리 출력당
전체화면 하나다. 같은 모니터의 left/right는 테스트용 분할이며 서로 겹치지 않아야 한다.
간편 설정으로 프로필·서비스·부팅 등록을 준비한다. 화면 관리의 **설정**에서 사이트를
저장한 다음 **설정 적용**을 선택한다. 저장 주소와 적용 주소는 상세 영역에서 확인한다.
적용은 현재 확정된 화면 코드로 선택한 대상만 전환한다. 실행 중인 창은 준비 조건을
확인한 뒤 재시작하며, 중지 상태에서는 설정만 확정한다.

**재시작**은 적용된 설정으로 Chrome을 다시 띄운다. **페이지 새로고침**은 실행 중인
Chrome에서 적용된 사이트를 다시 읽는다. **배포 재시도**는 프론트 배포 연동에서 실패한
갱신을 다시 요청한다. 버튼에 포커스를 두거나 마우스를 올리면 동작 설명이 표시된다.

`default`는 기존 `ala-chrome.service`와 `~/.config/ala/chrome-display`를 보존한다.
추가 대상은 `ala-chrome@<ID>.service`와 별도 표시 프로필을 사용한다. 일반 Chrome이나
다른 대상 프로필을 종료·복사·삭제하지 않는다. 중지는 현재 실행만 중지하며 자동 시작을
계속 끄려면 대상 설정을 변경한다. 업데이트는 수동 중지 대상을 다시 켜지 않는다.

## 관측 범위

- Chrome 실행: 서비스와 UID·부모·부팅·시작 식별자·실제 프로필을 확인한다.
- 창 배치: 전용 GNOME 확장이 실제 관리 창의 위치·크기·전체화면을 재조회한다.
- 사이트: 관리 문서 HTTP/로드와 복구 상태다. 앱 데이터 완전성·모니터 픽셀 검증이 아니다.
- 사이트 주소는 설정 주소와 일치 여부를 구분한다. 관측하지 못한 실제 주소를 추정하지 않는다.

확장은 GNOME Shell 47과 49에서 protocol 1을 사용한다. 지원하지 않는 버전이나 연결 실패는 정상으로
우회하지 않는다. 확장 첫 등록 후 GNOME 재로그인이 필요할 수 있으며 ala는 현재 GDM이나
세션을 강제로 재시작하지 않는다. 확장은 관리 Chrome만 다루며 임의 Shell/Eval API가 없다.

## 부팅 복구와 이전

GDM 자동 로그인 → GNOME autostart → 대상 사용자 서비스 → 확정된 관리 버전 순으로 실행한다.
자동 시작을 요청한 로그인에서는 ala GNOME 확장이 시작 애니메이션 뒤 활동 개요를 한 번 닫는다.
기존 장비는 CLI 갱신 후 간편 설정으로 확장 파일을 등록하고 다음 GNOME 로그인에서 확인한다.
로그인 이후에는 Super 키로 활동 개요를 열고 닫을 수 있다.
CLI 버전과 화면 관리 버전은 다르다. 현재 실행·다음 부팅·장애 재시작은 확정 선택을 사용하고,
새 코드는 검증 후 별도로 적용한다. 최초 RC20 이전은 [업데이트 절차](UPDATES.md)를 따른다.

PC가 정상 부팅되는 시점 이후가 관리 범위다. BIOS 전원 복구와 부팅 전 디스크 암호는 제외한다.
실제 GNOME의 창 식별·출력 배치·재부팅 표시는 자동 테스트와 별도로 수용한다.
