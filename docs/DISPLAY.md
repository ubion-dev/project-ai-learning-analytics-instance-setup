# 화면과 부팅 관리

`ala`의 화면 관리 탭에서 모니터 그림을 클릭하거나 방향키로 선택한 뒤 Enter를 누르면
해당 화면의 설정이 열린다. 메인에는 모니터와 상태, **모니터 식별·다시 조회**를 표시한다.
시작·중지·재시작·페이지 새로고침·로그·배포 재시도는 설정 창의 **운영** 영역에 모았다.
저장 주소·적용 주소와 Linux DRM 커넥터 연결 상태는 **상태 상세·작업 로그**에서 확인한다.
모니터 그림은 터미널 크기와 무관한 고정 모양이다. 확인된 물리 해상도와 GNOME 배율을
`3840×2160 · 150%`처럼 표시한다. 물리 모드를 확인하지 못하면 논리 영역임을 명시하며
복제 출력의 서로 다른 물리 해상도를 하나로 추정하지 않는다. 실제 픽셀
비율이나 GNOME 좌표를 편집하는 도구가 아니며 공간이 부족하면 줄바꿈·스크롤한다.
모니터와 출력 선택 목록은 GNOME이 확인한 활성 논리 화면을 사용한다. 복제 출력은 하나의 논리 화면으로
다룬다. 기본 대상은 활성 논리 화면이 하나일 때 자동 선택한다. 지정 출력이 연결
해제되면 설정을 보존하고 배치를 대기한다. `ala display list --json`에서 두 관측을 확인한다.

## 설정과 제어

처음 간편 설정을 실행하면 **모니터별 안내 화면 준비**가 선택돼 있다. 실행 전 생성할
DID와 자동 시작 변경을 확인한다. GNOME이 확인한 모든 논리 출력에 각각 안내 DID를
준비하고 일반 사용자 Chrome으로 화면 번호·연결 이름·사이트 설정 안내를 표시한다.
네트워크 없이 표시되는 내부 문서이며 실제 사이트 로드 정상과는 구분한다.

그래픽 세션이나 확장이 준비되지 않았으면 초기 준비 상태를 보존하고 15초 간격으로
재확인한다. 다음 정상 GNOME 로그인에서 이어서 준비하므로 간편 설정을 반복할 필요는
없다. 자동 재부팅이나 GDM 재시작은 하지 않는다. 기존 실행·수동 중지·다른 구성 변경은
보존하며, 완료 뒤 추가한 모니터에 DID를 자동 생성하지 않는다.

기존 미설정 장비의 안내 준비 옵션은 기본 꺼짐이다. 명시적으로 선택하고 변경을 확인하면
초기 준비를 진행한다. 사이트나 배포 연동이 있는 장비에는 이 초기화를 적용하지 않는다.
새 구성과 새 DID의 **로그인 후 자동 시작**은 기본 켜짐이며, 기존 저장 값은 보존한다.

대상마다 ID·사이트·출력 연결자·자동 시작·배치를 저장한다. 정상 운영은 논리 출력당
전체화면 하나다. 같은 모니터의 left/right는 테스트용 분할이며 서로 겹치지 않아야 한다.
간편 설정으로 프로필·서비스·부팅 등록을 준비한다. 화면 관리에서 모니터를 열고 사이트를
저장한 다음 같은 모니터를 다시 열어 **설정 적용**을 선택한다. 저장만으로 현재 화면을 바꾸지 않는다.
설정 창은 주기적으로 상태를 갱신해도 편집 중인 값을 유지한다. 미저장 편집이 있으면
로그 외 운영 작업은 먼저 저장하거나 창을 다시 열어 진행한다.
한 모니터에 여러 분할 DID가 있으면 설정할 DID를 먼저 고른다. 연결 해제·미배정·출력 확인
불가 대상은 **연결되지 않은 화면**을 펼쳐 연다. 이 영역에서 기존 **화면 추가**도 사용할 수 있다.
적용은 현재 확정된 화면 코드로 선택한 대상만 전환한다. 실행 중인 창은 준비 조건을
확인한 뒤 재시작하며, 중지 상태에서는 설정만 확정한다.
자동 시작 등록도 설정 적용에서 함께 동기화한다. 등록 확인 실패는 실제 화면 적용 결과와
구분해 표시한다. 안내 화면에서 주소를 저장만 한 상태와 실제 사이트로 적용한 상태도 구분한다.

### 모니터·작업 공간·Chrome 창 구분

모니터는 연결된 출력이고, 작업 공간은 같은 모니터에서 전환할 수 있는 가상 데스크톱이다.
Chrome 창이 다른 작업 공간에 있으면 모니터 좌표가 맞아도 현재 작업 공간에서 보이지 않을 수 있다.
DID 화면 계정의 간편 설정은 동적 작업 공간을 끄고 작업 공간 수를 하나로 준비한다.
DID 자동 시작을 처리하는 GNOME 로그인 경로에서도 같은 사용자 설정을 확인한다. 다른 계정의 설정이나 전역 dconf 잠금은
추가하지 않는다. 정책을 적용하면 기존 여러 작업 공간과 그 안의 창은 GNOME이 하나로 합칠 수 있다.
ALA는 창을 닫지 않으며, 아래의 개별 창 배치 기능은 현재 작업 공간을 강제로 전환하지 않는다.

현재 창 배치는 실제 사각형·전체화면 여부와 현재 작업 공간 소속을 함께 관측한다. 다른 작업
공간에 있는 관리 창은 해당 창만 현재 작업 공간으로 옮긴다. 사용자 작업 공간이 전환되거나
창·출력·프로세스 증거가 바뀌면 진행 중인 배치를 보류한다. 작업 공간 관측을 제공하지 않는
구버전 확장은 정상으로 추정하지 않고 확장 반영·GNOME 재로그인을 안내한다.

모니터마다 독립 사이트를 운영하려면 출력마다 별도 DID를 등록한다. 같은 Chrome에서 새 창을
여러 개 열었다는 사실만으로 DID가 추가되지는 않는다. 모니터 그림을 열어 새 DID와 출력·주소를
저장하고 설정 적용으로 등록한 뒤, 표시할 때 명시적으로 시작한다.

기본 화면 지도의 드래그는 DID 사이트의 출력 배정이다. OS 모니터의 좌우·상하 배치와
해상도·배율은 **모니터 배치·해상도**에서 별도로 편집한다. 저장 출력과 적용된 설정의
출력은 상세에서 구분하고, 실제 창 위치는 창 배치 관측을 확인한다.

### 모니터 배치·해상도·화면 배율

RC31에서 화면 관리의 **모니터 배치·해상도**를 연다. 연결된 모니터를 2차원으로 표시하며 세 대 이상·상하·여러 줄 배치를 편집한다. 모니터를 다른 모니터 위에 놓으면 위치를 교환하고, 빈 공간에 놓으면 이동한다. 드래그 중에는 교환 상대를 강조만 하며 드롭 완료 전에는 상대 위치와 편집값을 바꾸지 않는다. 사이트 배정은 기존 출력에 유지한다.

모니터 선택 뒤 해당 출력이 실제로 지원하는 해상도·주사율·화면 배율을 선택한다. 해상도 변경으로 기존 배율이 지원되지 않으면 빈 선택으로 남겨 재선택을 요구한다. 전체 모니터에 같은 배율이 필요한 환경은 다른 값을 적용하지 않는다. **이 모니터의 사이트**로 기존 사이트 설정·저장·설정 적용 동선을 연다. 좌표는 고급 입력으로도 지정할 수 있다.

**변경 검토 → 배치 적용 → 화면 확인 → 이 배치 유지** 순서로 진행한다. 적용 후 실제 관측부터 30초 동안 응답을 기다린다. 취소하거나 응답이 없으면 복원을 요청한다. **다음 로그인에도 유지**는 기본 켜짐이다. 이를 끄면 현재 세션에서만 시험하며, 기존 저장 프로필은 수정하지 않는다. 고급 입력의 **저장 배치 로그인 복원 끄기**로 이전 프로필의 자동 복원을 명시적으로 중지할 수 있다.

기존 설치에서는 **확장 갱신**으로 새 파일과 활성화를 준비하고, GNOME에서 한 번 로그아웃한 뒤 다시 로그인해야 새 확장 코드가 로드된다. SSH 재접속과는 다르며, ala가 대신 로그아웃·GDM 재시작·재부팅하지 않는다. GNOME의 확장 모듈 캐시 때문에 단순 비활성화·활성화만으로 코드 갱신을 보장하지 않는다.

CLI 조회·계획은 다음과 같이 별도로 제공한다.

- `ala display modes --json`: 활성 GNOME 세션의 출력별 지원 모드·배율과 현재값을 조회한다. 반환한 `edit_template` 객체를 별도 JSON 파일로 준비한다. 전체 조회 응답 자체를 계획 입력으로 사용하지 않는다.
- `ala display plan layout.json --json`: 템플릿에서 각 출력의 `x`, `y`, `mode_id`, `scale`을 편집한 파일을 최신 출력 정보에 대조한다. 출력 ID·사이트 배정·주 모니터·회전은 공간 위치와 함께 바꾸지 않는다.

음수 좌표는 전체 배치의 왼쪽 위가 원점이 되도록 함께 정규화한다. 겹침·서로 떨어진 화면·모서리만 닿는 배치는 적용을 거부한다. 복제 출력 편집·출력 활성/비활성 전환은 제공하지 않는다.

`state: validated`는 로컬 검사를 통과했다는 뜻이다. 계획의 `backend_verified: false`, `apply_supported: false`는 해당 조회가 OS를 변경하지 않음을 나타낸다. 모니터 연결·설정이 바뀌면 새 템플릿으로 다시 준비한다. `modes`의 `trial_supported`는 연결된 확장의 세션 시험 기능 여부다.

- `ala display trial layout.json --json`: 공통 변경 잠금 안에서 구성·모드·GNOME 세션을 재대조하고 Mutter의 검증 호출을 거친다. 별도 systemd 실행기가 현재 세션에 배치를 적용하고 다시 관측한 뒤 30초 동안 확인을 기다린다. 반환한 작업 ID를 확인한다.
- `ala display apply layout.json --json`: 같은 확인 절차를 사용하되 확정 시 로그인 복원 프로필을 저장한다. 파일 입력만으로 즉시 확정하지 않는다.
- `ala display trial-status --json`: 가장 최근 시험의 상태와 작업 ID를 읽는다. `awaiting_confirmation`일 때 화면을 직접 확인한다. 조회는 복구를 자동 실행하지 않는다.
- `ala display confirm --operation-id WORK_ID --json`: 같은 시험의 확정 응답을 접수한다. 응답 접수는 최종 확정과 다르므로 `trial-status`에서 `confirmed`를 확인한다.
- `ala display revert --operation-id WORK_ID --json`: 같은 시험에 복원 응답을 접수한다. 확인이 없거나 시간이 지나도 실행기가 원래 배치로 복원을 요청하고 실제 출력을 재검사한다.
- `ala display recover --operation-id WORK_ID --json`: 남아 있는 복구 작업을 명시적으로 재시도한다. 실행 중인 시험이 공통 잠금을 소유하면 완료 후 재검사한다. 과거 작업 ID로 최신 시험을 변경하지 않는다.

`trial`은 `persistent: false`인 세션 시험이고, `apply`는 확정 시 ala 프로필에 저장한다. `monitors.xml`이나 GNOME의 고유 영구 설정을 직접 쓰지 않는다. root 서비스 `ala-monitor-profile.timer`가 15초 간격으로 새 GNOME 확장 세션을 확인한다. 저장 당시의 계정·출력 식별 정보 해시·활성 구성·모드·배율·주 모니터·회전·좌표 방식이 맞을 때 동일 검증 실행기로 다시 적용하고 실제 결과를 확인한다. 일련번호를 제공하지 않는 모니터의 개체 식별까지 보장하지는 않는다. 같은 확장 세션에서 사람이 바꾼 배치를 주기적으로 되돌리지 않으며, 불일치는 자동 적용을 보류하고 고급 입력에서 복원 재시도를 제공한다.

SSH 클라이언트와 독립한 실행기 및 `ExecStopPost` 복구를 등록한다. 미확정·복구 필요 기록이 남으면 다른 ala 변경과 CLI 설치·갱신을 차단한다. 세션 종료·확장 비활성화·잠금·연결 변경·외부 설정 변경 등으로 안전한 복원을 확인할 수 없으면 `recovery_required`를 유지한다. 무조건 복원됐다고 표시하지 않으며 GNOME 화면 설정을 확인하고 복구를 재시도해야 한다. 복제 출력·임대 출력·비기본 RGB 범위의 배치 변경은 거부하며, 지원되는 underscanning·색 모드와 주 모니터·회전을 보존한다. 실제 Rocky 수용 항목은 [수용 기록](ACCEPTANCE.md)에 남긴다.

GNOME 공식 [DisplayConfig 규약](https://raw.githubusercontent.com/GNOME/mutter/gnome-49/data/dbus-interfaces/org.gnome.Mutter.DisplayConfig.xml)은 검증·임시 적용·영구 적용을 서로 다른 메서드 값으로 구분한다. 이번 임시 적용의 복원 책임은 ala 실행기와 복구 기록에 있으며, Mutter가 임시 적용만으로 자동 복원한다고 간주하지 않는다.

### 모니터 식별

**모니터 식별**을 선택하면 모든 활성 논리 화면에 `화면 1 · HDMI-1` 같은 표지를
10초간 표시한다. TUI 배치도의 `#1`과 실제 화면의 `화면 1`은 같은 번호다. 사이트·창
위치·포커스는 바꾸지 않는다. 표지는 시간이 지나면 사라지며 연결 변경·잠금·확장 종료 시
정리된다. 표시 요청 성공만으로 실제 패널의 표시를 확인했다고 판단하지 않는다.

번호는 현재 연결된 논리 출력 ID순의 별칭이다. 연결이 바뀌면 번호를 다시 확인하고,
영속 배정에는 출력 ID를 사용한다. 복제 출력은 동일 번호 하나로 표시하며 외부 분배기 뒤
패널을 개별 식별하지 않는다. 이 기능은 지원하는 확장과 활성·잠금 해제 GNOME 세션이 필요하다.

#### 식별 기능을 제공하지 않는다는 안내가 나올 때

`현재 GNOME 세션의 화면 확장은 모니터 식별 기능을 제공하지 않습니다`는 연결된 확장의
응답에 식별 기능이 없다는 뜻이다. DID의 Chrome 실행 실패와 별도로 판단한다.
CLI 배포 파일, 시스템에 설치된 확장 파일, 현재 GNOME이 읽어 실행하는 코드는 갱신 시점이 다르다.
`ala update`는 CLI 배포를 전환하며 시스템 확장 파일을 갱신하지 않는다.

먼저 다음 읽기 전용 명령으로 확장 파일 두 개의 상태만 확인한다. 실제 계정·사이트·장비 정보를
출력하지 않는다.

```bash
ala status --json | python3 -c '
import json, sys
report = json.load(sys.stdin)
results = {item["id"]: item for item in report.get("results", [])}
for name in ("display.extension.extension.js", "display.extension.metadata.json"):
    print(name, results.get(name, {}).get("state", "unknown"))
'
```

- 둘 다 `ok`: 현재 CLI 배포와 설치된 시스템 파일이 일치한다. 표시를 중단할 수 있는 시간에
  GNOME 데스크톱에서 로그아웃·로그인한 뒤 다시 식별한다. SSH 재접속은 GNOME 세션을 갱신하지 않는다.
- `change_required`: 간편 설정의 변경 항목을 확인하고 기존 구성을 유지해 확장 파일을 반영한다.
  모니터별 안내 초기화와 추가 Bash 설치는 선택하지 않는다. 완료 후 GNOME 데스크톱에 다시 로그인한다.
  파일이 갱신되기 전에는 재부팅만 해도 예전 확장이 다시 실행될 수 있다.
- `blocked`·`unknown`·검사 항목 없음: 파일·권한·조회 상태를 먼저 확인한다. 최신이라고 추정하거나
  반복해서 재부팅하지 않는다.

두 파일이 `ok`이고 GNOME 재로그인 후에도 같은 안내가 나오면 실제 로드된 확장 경로와 사용자별
중복 설치 여부를 확인한다. Chrome 재시작이나 DID 설정 적용은 GNOME 확장 파일 갱신을 대신하지 않는다.

### RC29 작업 공간·배치 변경 적용

기존 장비는 `ala update --prerelease` 뒤 ALA를 다시 열고, 간편 설정에서 기존 구성을 유지해
확장 파일과 DID 계정의 작업 공간 정책을 반영한다. 모니터별 안내 화면을 다시 초기화할 필요는 없다.
그다음 GNOME 데스크톱에 다시 로그인한다. SSH 재접속만으로는 실행 중인 확장이 바뀌지 않는다.

CLI 버전과 DID별 화면 코드 버전은 별도로 유지된다. **업데이트 → 자동 운영 → 선택 화면 코드 적용**
또는 `ala update --apply-runtime default`로 해당 DID의 코드를 명시적으로 전환한다. 다른 DID는
실제 등록한 ID를 사용한다. 최초 서명 검증 준비가 필요하면 [최초 한 번 준비](UPDATES.md#최초-한-번-준비)를
따른다. 필요한 확장이 로드되지 않았다면 기존 창을 교체하기 전에 적용을 보류한다.
중지한 DID는 코드 전환으로 자동 시작하지 않는다. 준비가 끝난 후 화면 관리에서 선택한 DID를
명시적으로 시작하고, 실제 모니터와 빠른 점검에서 위치·작업 공간·사이트 표시를 확인한다.

### 사이트를 다른 모니터로 이동

화면 관리에서 DID가 하나 배정된 모니터 그림을 다른 모니터로 드래그한다.
클릭은 설정만 열고, 일정 거리 이상 끌었을 때 이동·교환 확인으로 이어진다.
확인 창의 DID·사이트·출력 방향을 검토하고 **이동 적용**을
선택하면 해당 DID의 출력만 저장하고 기존 설정 적용 절차로 전환한다. 실행 중인 DID는
잠깐 재시작될 수 있다. 중지된 DID는 배정만 확정하며 **시작**은 별도로 선택한다.

Escape나 확인 창의 **취소**, 출력 밖에 놓기, 같은 출력에 놓기는 설정을 변경하지 않는다.
확인 중 설정이나 모니터 연결이 바뀌면 다시 조회하고 이동해야 한다. 기존 설정 적용이나
다른 작업이 진행 중이거나 분할 화면·여러 DID가 겹친 출력은 이동을 차단한다.

배치는 이전 전체화면을 불필요하게 해제하지 않고 목적 출력·작업 공간의 실제 반영을 확인한다.
새 전체화면 진입 전에는 목적 출력으로 이동한 근거를 기다린다. 사용자가 실제 창을 마우스로 끌고 있는 동안에는
자동 보정을 보류하며, 수동 이동 뒤에도 저장된 배정은 유지한다. 영속적인 출력 변경은 TUI에서
저장·적용한다. 다른 창과 연결된 관리 창은 함께 이동할 수 있어 자동 배치를 차단한다.

대상 출력에 전체화면 DID 하나가 있으면 **두 화면 교환 적용** 확인창에서 두 DID의
현재·적용 후 배정을 확인한다. 안내 화면도 교환 상대가 될 수 있다. 두 DID의 출력만
맞바꾸며 사이트 주소·대상 ID·프론트 설정·자동 시작·중지 상태는 각 DID에 남는다.
두 화면이 잠깐 끊길 수 있으며, 중지된 DID는 교환으로 켜지지 않는다.

교환은 SSH 종료와 독립된 작업으로 실행하고 재접속 뒤에도 같은 작업 ID로 조회한다.
확정 전 실패·중단은 원래 배정으로 복구하고, 확정 후 중단은 새 배정으로 정리한다.
교환 중 수동 중지는 우선하며 중지한 DID를 자동으로 되살리지 않는다. 복구를 확인하지
못하면 추가 변경을 막고 해당 모니터 설정 창의 **두 화면 교환 복구 재시도**와 대상별 상태를 제공한다. 자동 복구 실패를
무한히 반복하지 않는다. 실제 창 복구와 배정 선택의 복구는 별도로 확인한다.

이동 후 상태와 다음 조치, 창 배치를 다시 확인하고 실제 모니터의 표시도 확인한다.
이 기능은 DID의 모니터 배정을 바꾼다. GNOME의 모니터 좌표·해상도는 변경하지 않는다.
마우스를 사용할 수 없는 터미널에서는 **방향키 → Enter → 출력 선택 → 저장 → 다시 열어 설정 적용**을 사용한다.

**재시작**은 적용된 설정으로 Chrome을 다시 띄운다. **페이지 새로고침**은 실행 중인
Chrome에서 적용된 사이트를 다시 읽는다. **배포 재시도**는 프론트 배포 연동에서 실패한
갱신을 다시 요청한다. 버튼에 포커스를 두거나 마우스를 올리면 동작 설명이 표시된다.

`default`는 기존 `ala-chrome.service`와 `~/.config/ala/chrome-display`를 보존한다.
추가 대상은 `ala-chrome@<ID>.service`와 별도 표시 프로필을 사용한다. 일반 Chrome이나
다른 대상 프로필을 종료·복사·삭제하지 않는다. 중지는 현재 실행만 중지하며 자동 시작을
계속 끄려면 대상 설정을 변경한다. 업데이트는 수동 중지 대상을 다시 켜지 않는다.

## 관측 범위

- Chrome 실행: 서비스와 UID·부모·부팅·시작 식별자·실제 프로필을 확인한다.
- 창 배치: 전용 GNOME 확장이 실제 관리 창의 위치·크기·전체화면을 재조회한다.
- 사이트: 관리 문서 HTTP/로드와 복구 상태다. 앱 데이터 완전성·모니터 픽셀 검증이 아니다.
- 사이트 주소는 설정 주소와 일치 여부를 구분한다. 관측하지 못한 실제 주소를 추정하지 않는다.

확장은 GNOME Shell 47과 49에서 protocol 1을 사용한다. 지원하지 않는 버전이나 연결 실패는 정상으로
우회하지 않는다. 확장 첫 등록 후 GNOME 재로그인이 필요할 수 있으며 ala는 현재 GDM이나
세션을 강제로 재시작하지 않는다. 확장은 관리 Chrome만 다루며 임의 Shell/Eval API가 없다.

CLI 업데이트만으로 실행 중인 GNOME 확장이나 선택된 DID 런타임이 바뀌지는 않는다.
구버전이 식별·안내·교환을 지원하지 않으면 안내에 따라 간편 설정으로 확장 파일을 준비하고
다음 GNOME 로그인에서 확인한다. DID 화면 코드는 업데이트 관리의 선택 화면 코드 적용으로
전환한다. 기존 사이트의 코드 전환과 안내 초기화를 혼동하지 않는다.

## 부팅 복구와 이전

GDM 자동 로그인 → GNOME autostart → 대상 사용자 서비스 → 확정된 관리 버전 순으로 실행한다.
자동 시작을 요청한 로그인에서는 ala GNOME 확장이 시작 애니메이션 뒤 활동 개요를 한 번 닫는다.
기존 장비는 CLI 갱신 후 간편 설정으로 확장 파일을 등록하고 다음 GNOME 로그인에서 확인한다.
로그인 이후에는 Super 키로 활동 개요를 열고 닫을 수 있다.
CLI 버전과 화면 관리 버전은 다르다. 현재 실행·다음 부팅·장애 재시작은 확정 선택을 사용하고,
새 코드는 검증 후 별도로 적용한다. 최초 RC20 이전은 [업데이트 절차](UPDATES.md)를 따른다.

PC가 정상 부팅되는 시점 이후가 관리 범위다. BIOS 전원 복구와 부팅 전 디스크 암호는 제외한다.
실제 GNOME의 창 식별·출력 배치·재부팅 표시는 자동 테스트와 별도로 수용한다.

## DID 전체 초기화

화면 관리의 모니터 목록 아래 **관리 도구 → DID 전체 초기화**에서 현재 구성과 변경 대상을 검토한다. 기본 포커스는 취소이며 승인 전에는 백업 생성·구성 저장·Chrome 제어를 하지 않는다.

승인하면 현재 사이트·배정·자동 시작·프론트 연동과 런타임 선택, 관리 unit·로그인 등록을 먼저 백업하고 무결성을 확인한다. 검토한 논리 모니터마다 URL 없는 전체화면 안내 DID를 만들고 자동 시작을 켜며 프론트 연동을 끈다. 기존 수동 중지를 해제하고 안내 화면을 시작한다는 의도도 확인창에서 검토한다. 승인 이후의 수동 중지는 항상 우선한다.

계정·Bash·SSH·Docker·드라이버·GNOME 정책·코드 버전·자동 운영 정책과 Chrome 프로필은 유지한다. 사이트 설정 초기화는 쿠키·로그인 정보 삭제가 아니다. 동일 ID의 프로필에는 기존 로그인 정보가 남을 수 있다. 관리되지 않은 Chrome 창은 닫지 않는다.

모든 기존 화면 코드와 새 DID에 사용할 코드가 `display_reset_protocol: 1`, 안내 모드와 작업 공간 배치를 지원해야 한다. 현재 GNOME 확장도 작업 공간 배치를 제공해야 한다. 지원이 없으면 기존 화면을 중지하기 전에 코드 적용·확장 반영을 안내한다. 이 기능은 게시된 RC29에 소급 추가되지 않으며, 기능을 포함한 새 배포를 설치해야 한다.

### 진행·백업과 복구

초기화는 SSH와 독립된 고정 systemd 작업으로 실행한다. 작업 ID·상태·대상과 백업 위치는 관리 도구에서 다시 확인할 수 있다. 백업은 `/var/lib/ala/display-resets/<작업ID>.json`에 기존 구성·선택·등록 내용을 포함해 저장한다. 디렉터리 0700·파일 0600의 관리자 전용 기록이므로 원본을 공개 게시물이나 로그에 첨부하지 않는다. Chrome 프로필을 복사한 백업은 아니다.

- commit 결정 전 중단: 이전 배정을 복구하고 원래 실행 중이던 DID만 다시 시작한다. 새로 중지한 DID는 켜지 않는다.
- commit 결정 후 중단: 새 안내 배정을 끝까지 일관되게 확정한다. 이전 사이트와 새 안내가 섞인 채 시작하지 않는다.
- 재부팅: GUI보다 먼저 배정을 복구하고, GNOME 준비 전에는 실행을 보류한다. 15초 간격으로 최대 10분 동안 준비를 확인한 뒤 실행 의도를 재개한다. 원래 자동 시작이 꺼져 있어도 실행 중이었던 DID의 복구 의도는 별도로 보존한다.
- 종료·배치·문서 확인 실패, 대기 시간 초과: 대상별 상태와 복구 필요를 표시하고 자동 재시도 타이머를 중지한다. 세션·연결·로그를 확인한 뒤 **초기화 작업 복구**를 명시적으로 요청한다.

완료 후 타이머는 해제하지만 백업·부팅 복구 서비스·감사 기록은 보존한다. 완료된 초기화를 이전 사이트로 되돌리는 별도 복원 버튼은 이번 범위에 없다. 실제 모니터의 안내 표시는 운영자가 확인하며, 서버의 실행 후조건 확인과 구분한다.

제외된 DID의 기록과 프로필은 보존하되 로그인·예약 실행·일반 시작에서 차단한다. 같은 ID를 직접 재등록해 오래된 사이트가 되살아나지 않도록 보호하므로 수동 추가에는 다른 ID를 사용한다. 자동 생성 ID와 보존 기록이 충돌하면 임의 삭제나 이름 변경 없이 초기화를 차단한다.
