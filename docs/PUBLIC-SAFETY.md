# 공개 저장소 데이터 보호

이 저장소의 파일과 전체 Git 이력, PR 본문, CI 로그, 릴리스에 실제 운영 데이터를 게시하지 않는다.
개인 이메일·비루프백 IP·실제 접속 주소/계정·고객/장비 식별정보·암호/토큰/개인키는 금지한다.
사설·VPN 주소와 문서용 주소도 IP 리터럴로 저장하지 않는다. 테스트는 루프백 주소와 example.com 계열만 사용한다.
주소 분류 테스트는 문서용/링크 로컬 합성 주소를 실행 중에 생성하되 실제 장비 값이나 IP 문자열을 저장하지 않는다. CI는 실패 traceback·캡처 출력을 공개하지 않는다.
공식 문서·패키지 다운로드 호스트는 검사기의 명시적 목록으로 제한한다.

## 개발 PC 설정

공식 [Gitleaks](https://github.com/gitleaks/gitleaks)를 설치한다. CI는 고정 버전과 SHA-256을 검증한다.
GitHub Settings → Emails에서 본인의 noreply 주소를 확인한 뒤 저장소의 `user.email`로 지정한다.
다른 사람의 noreply 주소를 복사하지 않는다. GitHub가 병합 시 사용하는 noreply@github.com도 공개용 시스템 주소로 허용한다.

```bash
bash scripts/install-git-hooks.sh
python3 scripts/check-public.py --staged
python3 scripts/check-public.py --history
```

- pre-commit: 작업 폴더가 아닌 스테이징된 파일 전체와 작성자/커미터 이메일을 검사한다.
- pre-push: 전송할 각 브랜치/태그가 참조하는 전체 조상 이력까지 검사한다.
- CI: shallow clone 없이 전체 이력을 검사한다. 오류·도구 부재도 실패 처리하며 발견 문자열을 출력하지 않는다.
- Gitleaks의 기본 규칙과 별도의 IP·이메일·URL 검사 모두 통과해야 한다. 저장소 내 무시 파일/주석으로 비밀정보 검사를 우회하지 않는다.
- 훅 설치는 다른 hooksPath를 덮어쓰지 않는다. 기존 훅이 있으면 검사 호출을 통합해야 한다.

## 보호 범위와 한계

로컬 훅은 각 복제본에서 설치해야 하며 Git 옵션으로 우회할 수 있다. CI는 이미 공개 푸시가 이뤄진 뒤 실행되므로 유출 자체를 되돌리는 장치가 아니다.
GitHub의 필수 상태 검사 설정과 비밀정보 push protection은 별도 서버 정책이며 이 스크립트 설치만으로 활성화되지 않는다.

일반 사용자명·평문 문자열이 실제 비밀번호인지 자동 판별하는 것은 보장할 수 없다. 임의의 운영 출력·스크린샷·첨부 파일은 공개 PR에 붙이지 않는다.
테스트의 인증 거부/마스킹 검증에는 명백한 합성 값만 사용한다. 공식 호스트 목록 확대와 검사 변경도 리뷰 대상이다.
CI 오류 로그에는 원문을 출력하지 않는다. 필요한 로컬 조사는 화면 공유/로그 공개 없이 진행한다.

과거에 공개된 Git 객체·PR diff·다운로드 사본은 이력 재작성만으로 완전히 회수할 수 없다. 실제 비밀정보를 게시했다면 해당 자격증명 폐기·교체와 별도 삭제 조치가 필요하다.

## 저장소 적용 상태

2026-11-02 GitHub secret scanning과 push protection을 활성화했다. 지원되는 인증정보 패턴에 대한 서버 측 보호이며 모든 평문 비밀번호/IP/개인정보를 판별하는 기능은 아니다. 공개 데이터 CI 검사는 기본 브랜치에도 적용한다.

main의 `public-data` 검사를 필수 상태 검사로 설정했고 관리자에게도 적용한다. 최신 base와의 검증을 요구하며 main의 강제 푸시·삭제는 허용하지 않는다. 이력 정리가 다시 필요하면 별도 승인과 보호 정책 검토가 필요하다.
